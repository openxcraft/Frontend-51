# 08 — Integration Map: abandoned-cart-recovery

AI declaration (ai-native-patterns §1): **conditionally-AI, one surface** — bilingual recovery-copy generation (`generateMessageVariants` + its draft read/promote pair, 07b) bound to an abstract generation capability; it degrades to the template library when unbound, consent-less, rate-limited, or failed. Everything else — intake rules, banding, priority scoring, quiet-hours deferral, suppression, expiry, reporting, export — is deterministic rule execution (07c) and requires no capability at all. Architecture speaks only in abstract capabilities; UI copy says kind, never vendor (credential-contract §2); the 00 success signals pass with every capability unbound (tested against the Mock's all-off configuration — 07c MockConfig defaults).

## Capability binding gates (LOOP-7 posture — evaluated at binding time, not now)

- **N1 parse fidelity**: a fixed cart evaluation set (field retention, bilingual item-name survival, last-activity fidelity — the anchor of every downstream clock) must pass before N1 ships active; an import that mangles `lastActivityAt` poisons every schedule the product computes (07c rule 2's anchor arithmetic).
- **N2 dispatch fidelity**: typed error returns on dispatch failure (the 7-class taxonomy — a channel that fails silently is a ledger lie); idempotent dispatch keyed by sendId (retries never double-send); no partial-message truncation — the ledger's `dispatched` state means the whole message left.
- **N3 event hygiene**: event idempotency by eventKey honored end-to-end (duplicate web-callbacks write once, 07b rule 7); no synthesized engagement events (a channel that reports clicks that never happened corrupts the funnel AND the priority score's engagement component — 07c §D); opt-out events delivered within the channel's own SLA, because suppression is the compliance spine (07a state obligation).
- **N4 generation gates**: P13 streaming discipline (reserved dock region, stop/regenerate, partial marking), P14 metering with the 80% warning, P15 double gate (structural, not procedural), Arabic register consistency (فصحى بيضاء enforced; drift flagged inline, never silently corrected — ai-native-patterns §7), tashkeel off by default with the line-height warning when enabled. All five are non-negotiable at binding; the deterministic core never depends on any of them.
- **N5 address hygiene**: members only, workspace-scoped; notifications carry job/opt-out context, never message bodies or contact handles (data-minimization per credential-contract §7).

## Degradation map (ai-native-patterns §8)

| Surface | All capabilities unbound (default v1 posture) | Any capability failing mid-session |
|---|---|---|
| Recovery queue, cart detail, sequences, templates, policies, send ledger, suppression, report | **Full function** — intake rules, banding, priority, quiet-hours deferral, expiry, and reporting are local deterministic rules (07c); nothing pauses | Full function — capability failures surface only on their own affordances, typed per the 7-class taxonomy (P20 offline banner for transport loss) |
| Cart intake | Paste import (the primary path — 07c grammar demonstrated by the sample) | N1 failure → typed error + paste path offered inline (CP-1 failure row) |
| Dispatch | Sends hold in the ledger; send-list export is the dispatch path; manual event entry closes outcomes | N2 failure per send → `failed` state with typed error, needsDecision flag, and the export path named (CP-3.3 — deferred dispatch is a legitimate holding state) |
| Outcomes | Manual event entry (provenance `manual`, ledger peer) | N3 failure → outcomes wait for manual entry; the funnel honestly thins rather than fabricating (report derives from recorded events only — 07c rule 11) |
| Generation dock | **Rung 3**: the template library, labeled "non-generative — your library" (ai-native-patterns §5); authoring, scheduling, reporting untouched | N4 failure/rate-limit → rung ladder with reset time; partial variants kept and marked; the dock never writes into a sequence regardless of state |
| Notifications | In-app center + jobs console return state | N5 failure → in-app surfaces unchanged |

The quota ladder applies only to the metered operations (generation variants, export packages — P14, `getUsage`); the deterministic core is never metered and never degrades — there is no rung below "the rules run".

## Risk flags for the owner

- **N2 is the highest-leverage binding** (manual dispatch at volume is the paste-path's ceiling), and the one with compliance exposure: the binding gates above (idempotency, typed failures, opt-out delivery) are the minimum bar, and the quiet-hours contract (07c rule 4) evaluates BEFORE anything is handed to a channel — a channel with its own timing logic must never become a second scheduler.
- **N1's absence caps freshness, not function**: paste-imported carts carry historical `lastActivityAt` values, so early steps can dispatch immediately at import (07c rule 6) — honest, but it means recovery quality degrades with paste cadence; the owner should treat N1 binding as an operations decision, not a technical one.
- **N4's uplift is unbenchmarked in this corpus** (01 honest gaps — no Arabic recovery-copy effectiveness data surfaced; 12 Q-12): the generation surface prices and behaves as an assist, never as a claimed lift; if the owner wants uplift claims, that is a measurement program, not a feature.
- **Cross-product double-messaging is an owner-level coordination risk, not an integration**: recovery sequences (this product) and pre-delivery confirmation ladders (cod-order-confirmation) must never message the same buyer in the same window — a governance decision recorded in both 12s (LOOP-3 mirror), deliberately NOT a v1 live join.
