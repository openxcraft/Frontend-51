## Typography (P14 — Rubik + Space Mono)

- **Arabic: Rubik** (real weights 400/500/700 bound; the family's axis is broader — the spec designs within three): 400 body, 500 labels and table headers, 700 the single H1 per screen and note summaries' emphasis. A rounded-cornered, low-contrast Arabic that reads as the schedule-clerk's hand — closer to stamped forms than calligraphy.
- **Latin: Rubik (Latin)** for prose at the same three weights — one family, both scripts, P14's quirk-tech register without a third face. **Space Mono** (real weights 400/700 only, no synthetic bold): the CODE surface — HS codes, duty rates, note reference numbers, edition tags, counts. Codes are the product's primary object; mono tabular digits make a 12-digit line scannable, copy-safe, and visually distinct from prose by construction (the skill's mono-for-data instinct converges with the ledger pairing itself — see integration record).
- **Digit-group rule**: HS codes render with visible grouping (0207.14.00.10 fixture shape) in Space Mono 400, `dir="ltr"` isolated inside any Arabic prose (rtl-rules §2); rates render "5%" with the percent glyph attached in LTR isolation; counts in tables render mono 400.
- Line-height: Arabic 1.6 / Latin 1.5; tracking 0 for Arabic everywhere (token-level, rtl-rules §3); Space Mono carries its natural advance — no tracking changes on codes, ever (a code that drifts is a code misread).
- **Numerals: Western** (ledger row; data/reference surface per design-language-map §7): codes, rates, counts, dates, note refs all 0-9 in both locales; Arabic-Indic numerals never appear in system chrome (storage canonical, display formatted — rtl-rules §3).
- One pairing for reading AND chrome (T3 discipline; Space Mono is the ledger-declared code face of the pairing, not a third family added by preference).

## Shape, elevation, iconography, motion

- **Radius A (cut, 0–4px)**: table rows 0 (square ruled grid), cards and dialogs 4px, inputs 2px, chips 4px — the tariff register is squared paper. No fully-rounded exceptions: filter chips are cut rectangles with a removal glyph (a declared rejection of the pill default — see integration record conflict 6).
- **Elevation: flat-line**: hairline bronze-tinted borders carry all structure; hierarchy is expressed by border weight and the canvas→raised step (0.965→0.985); the reading pane's code card is the "deepest" surface by border weight alone. Zero shadows, no glass, no blur, no gradient (rejected below).
- **Icons: outline-geometric** (constructed-grid outline set, 1.5px constructed strokes on a geometric grid): nomenclature glyph = 3-tier lattice tree · search = square-corner magnifier · notes = stacked sheets with corner fold · lists = bookmark-pin on a ruled row · editions = two offset half-frames with a delta tick · activity = console prompt glyph · settings = gear-cut square · section/chapter markers = broad bracket / numbered chip. Directional glyphs (tree chevrons, breadcrumb separators, pagination arrows) flip in RTL; semantically anchored glyphs (magnifier, bookmark, sheets, gear) never flip (rtl-rules §2). No sparkle or wand glyphs anywhere — assist affordances render as a lattice mark + written "assist" label (ai-native-patterns §1: no magic affordances).
- **Motion: minimal** (motion-language §1): opacity-only transitions ≤120ms; position changes instant with crossfade; route changes hard-cut or ≤120ms crossfade; modals fade 0.98→1.0 ≤120ms with focus trap and return. The nomenclature never moves while being read.
- **Signature micro-interaction (exactly one, T3)**: **"the code settles."** When a tariff line is selected (from search, tree, note, or list), the reading pane's code block renders the full digit-grouped code in Space Mono with a two-step opacity settle (0% → 60% → 100%, ≤120ms total) and a polite screen-reader announcement of the code + level path. Digits never animate individually; the code never types itself out (a code that appears to be "computed" would undermine the reference posture); the settle exists so the eye lands on the code as the page's anchor object. Reduced-motion: the code renders at full opacity instantly with the same announcement — identical information, zero motion (motion-language §5).
