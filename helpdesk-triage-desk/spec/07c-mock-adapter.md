## Deterministic computation rules (the whole engine — specified exactly)

1. **Normalization pipeline** (applied to signature terms, urgency keywords, subject+body, and search input; the applied ruleset is disclosed in-product per ai-native-patterns §7.4): strip tashkeel (U+064B–U+065F, U+0670) and tatweel (U+0640); unify alef variants (أ إ آ ٱ → ا); taa marbuta (ة → ه); alif maqsura (ى → ي); Latin: case-fold, trim, collapse internal whitespace.
2. **Language detection** (never a model): over the normalized subject+body, count Arabic-script letters (U+0621–U+064A + unified forms) = `arCount` and Latin letters = `latCount`; `arRatio = arCount / (arCount + latCount)` (0 when both zero → `en`, the empty-body edge). `arRatio ≥ 0.70 → 'ar'`; `arRatio ≤ 0.30 → 'en'`; otherwise `'mixed'`. A recorded override freezes the value forever (07a).
3. **Keyword-rule clustering**: for every non-archived cluster, `matchedTerms` = the distinct signature terms (ar and en lists pooled) that occur in the ticket's normalized subject+body by word-boundary containment; assignment to cluster C iff `|matchedTerms(C)| ≥ C.matchThreshold` (default 2). Winner: (a) more distinct matches; (b) exact tie → the earlier-`createdAt` cluster; both candidates are recorded on the assignment when a tie occurred. `method: 'rule-match'`, `confidence = min(1, |matchedTerms| / matchThreshold)` (a deterministic ratio, not a model score). No cluster at threshold → the ticket stays **unclustered** — nearest-match guessing is forbidden (03 CP-2.5).
4. **Severity assessment**: urgency precedence `outage > security > billing > howto > none` — the highest class whose keyword list matches the normalized text wins, evidence = the matched term (verbatim quote). Impact = requester tier; **multi-user match escalates impact one tier** (standard→priority→key-account; key-account stays). `severity = matrix[effectiveImpact][urgencyClass]` (the seeded table above; workspace-editable, versioned). The assessment records all six signal classes with matched true/false — the named-signals contract. Overrides append with reason; the computed assessment is never rewritten.
5. **Assist-proposal simulation** (capability bound + consented ONLY; the conditionally-AI surface): unclustered tickets sharing ≥2 distinct normalized terms with ≥2 other unclustered tickets form a proposal group; label drafts = the two most frequent shared terms per script (en + ar). Per-ticket `confidence = min(0.88, 0.60 + 0.04 × distinctSharedTerms)` — a fixed formula, never a random draw; all resulting assignments carry `method: 'assist-proposal'` and the cluster `status: 'proposed'` until `confirmCluster` (07b rule 2 — the P15 gate). With the capability unbound: this rule does not execute at all and `runClustering` returns `engine: 'keyword-rules'` — the tested default state.
6. **SLA clock derivation** (read-time, from event history — never stored truth): `anchor(firstResponse) = receivedAt`; `anchor(resolution) = current routing decision.at`. `target` from the policy version in force at anchor. `elapsed = clock − anchor` minus paused spans (pending-requester windows on the resolution clock). `met` iff the closing event (first response log / closing disposition) timestamp ≤ `dueAt`; `breached` iff `elapsed > target` while unmet (a late close is recorded as breached-with-late-event, never retroactively met); `at-risk` iff `elapsed ≥ target × atRiskAtRatio (0.70)` while running and unmet. All arithmetic on the seeded clock.
7. **Routing-rule evaluation**: active rules sorted by `order` ascending; the first rule whose every declared condition matches the ticket's CURRENT facts (severity including overrides, current cluster, language, requester tier) routes; every other rule that ALSO matched is recorded in `suppressedMatches` by name. No match → `unrouted` with the full evaluation trace returned (which rules ran, which condition failed each).
8. **Merge**: children must be `new | clustered | routed`; keeper's severity = the highest severity in the set (record names the absorbed children and their severities); children close with disposition `duplicate` + `mergedFromTicketIds`; their assignments, notes, and response logs append to the keeper's history; keeper's cluster membership stands.
9. **Idempotency & dedupe**: identical `idempotencyKey` resubmits return the original result/job; channel intake with a seen `channelMessageId` returns the existing ticket.

## Behavior (per operation class)

- `createTicket` — empty subject → VALIDATION field-linked; `receivedAt` in the future beyond the seeded clock → VALIDATION; language detection + severity assessment execute synchronously on create (deterministic, local); channel path against a binding whose health ≠ active → PERMISSION naming the "message intake" capability class with the paste path offered inline; manual path has no consent requirement, ever.
- `updateTicket` — stale `baseRevision` → CONFLICT with both payloads; `languageOverride` freezes detection (recorded with actor); `requester.tier` change re-assesses severity live and returns the recomputed view (the UI must render it, not assume).
- `runClustering` — executes rules 3 (always) and 5 (capability-bound only); pacing determinate per ticket (fixed 40ms/10 tickets); partial failure injectable (`failClusteringAtTicket` — keyword assignments before the failure point are delivered and kept, failed scope named for retry); re-running on unchanged state produces identical assignments (the test oracle).
- `saveCluster` — labels required in BOTH locales → VALIDATION otherwise; signature terms normalized on save (disclosed in-editor); edits bump `version` and strand-warning: member tickets whose assignment no longer passes rule 3 under the new terms are named, and on commit they fall to **unclustered** (never silently reassigned); stale `baseVersion` → CONFLICT both kept; `status` may move confirmed→archived here (members fall to unclustered honestly) but NEVER proposed→confirmed (rule: only `confirmCluster`).
- `confirmCluster` — cluster not `proposed` → VALIDATION naming current status; missing/empty final labels → VALIDATION; on success: status flips, the cluster's `assist-proposal` assignments flip to `confirmed-cluster` with the confirming actor, and the activity entry records the gate.
- `assignToCluster` — cluster archived → VALIDATION naming status; `retractCurrent: false` while a current assignment exists → VALIDATION (the prior placement must be explicitly retired into history).
- `saveSeverityPolicy` — matrix sanity (every impact×urgency cell present; no P4 in a key-account×outage cell — the mock enforces ≥P2 there → VALIDATION "key-account outage cannot be P4"); targets sanity (firstResponseMinutes ≥ 5, resolutionHours ≥ firstResponse/60); stale baseVersion → CONFLICT.
- `runSeverityReassessment` — recomputes assessments for scoped open tickets against the named policyVersion; changed severities mark current routing decisions stale (routingReopened count); determinate pacing; idempotent per version.
- `routeTicket` — `method: 'manual'` without `reason` → VALIDATION; queue inactive → VALIDATION naming the queue; on success the routing decision records rule/suppressedMatches or the manual reason, and the resolution clock re-anchors to the decision's `at` (derived — rule 6).
- `bulkRouteTickets` — `confirmCount` mismatch against the live filtered set → CONFLICT with the recounted set; P1 and closed tickets in the set are skipped and named; success routes the rest with per-ticket decisions in the activity log.
- `escalateTicket` — missing `reason` → VALIDATION; `toSeverity` lower than current → VALIDATION ("escalations do not de-escalate — use a severity override with a reason"); P1 with `toSeverity: 'P1'` → VALIDATION naming the re-route path; success re-routes and records the escalation.
- `logTicketResponse` — on a closed ticket → VALIDATION naming the standing disposition; success sets the first-response clock's closing event (met-or-breached-late per rule 6).
- `setTicketDisposition` — `spam` without `confirm.spamAcknowledged: true` → VALIDATION (the P04 literal); duplicate-with-merge children in non-mergeable states → VALIDATION naming each; reversal of spam → VALIDATION (irreversible past its confirm); all other kinds reversible by appending a reversal event.
- `mergeTickets` — any child not `new|clustered|routed` → VALIDATION naming the child and its state; keeper absorbs per rule 8; result view lists the children.
- `exportTriageLog` — artifacts expire at creation + 7 days; `regenerable: true` always; partial failure injectable per format; idempotent re-submit returns the original job; the export carries per-ticket policy/cluster/rule version pins (the audit grammar).
- `getArtifact` — expired → NOT_FOUND with the regenerate path; regeneration is deterministic from triage state.
- `getUsage` — fixed window with seeded clustering-run and export counts; `quotaExhausted` injection exercises the RATE_LIMIT ladder copy (11).
- Channel ops — `createChannelBinding` starts `unverified`; `verifyChannelBinding` performs the round-trip (simulated deterministic success unless `failBindingVerify` injected → binding `failed` with correlationId); `revokeChannelBinding` sets `revoked` and retains the failure history; intake on non-active bindings pauses (queryable state, never silent drops by this product's contract).

`MockConfig { latencyMs (default 90), errorRate (default 0), errorCode?, failClusteringAtTicket?, failExportFormat?, quotaExhausted?, failBindingVerify? }` — per-method injection; fixed correlationIds `htd-corr-0001`…; failure responses follow the 7-token taxonomy of 07b exactly (VALIDATION · NOT_FOUND · PERMISSION · CONFLICT · RATE_LIMIT · NETWORK · UNKNOWN — the `errorCode` config injects any of the seven; UNKNOWN carries a correlationId and the retry-then-quote copy of 11). No random jitter: latency and failure points are configuration, not chance.
