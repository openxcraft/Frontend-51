## 2. The deterministic labor-rule engine (non-AI — exact arithmetic; the whole guardrail machinery)

1. **Worked-time computation.** For each assignment: span start `S = (weekStartsOn + dayIndex)·1440 + startMinute` (team timezone, minutes from the week's first midnight); span length `L = (endMinute − startMinute + 1440) mod 1440` — `endMinute < startMinute` is the explicit midnight-crossing signal (03 CP-1 edge); span end `E = S + L`; worked minutes `M = L − breakMinutes`. The break is one contiguous internal block placed at the span midpoint (floored to a whole minute) — it never alters span edges. Day attribution is by start day: a midnight-crossing shift's post-midnight tail counts toward its start day. Every rule below consumes this timeline; nothing else does.
2. **Cap precedence — stricter wins.** `effectiveDaily(worker) = min(enabled R_DAILY_MAX minutes, contract.dailyMaxMinutes if set)`; `effectiveWeekly(worker) = min(enabled R_WEEKLY_MAX minutes, contract.weeklyMaxMinutes)`. A disabled ruleset rule with no contract value → that cap class is unchecked (stock KSA/UAE v1 rely on contract caps for blocking daily/weekly maxima — the statutory standard hours express as the overtime *warnings* of rule 5, because scheduling legal overtime is lawful and must not be blocked). The roster-rail cap tooltip states both source values and the enforced one — never silent (07a). R_REST_GAP, R_CONSEC_DAYS, R_NIGHT_WINDOW, R_MAX_INCL_OT are ruleset-only at v1; Ramadan caps replace daily values in-window (rule 7).
3. **Rest gap (R_REST_GAP).** Order the worker's assignments by `S` across the prior published week (rule 6) plus the current plan; for each adjacent pair, `gap = S_next − E_prev`; `gap < required` → blocking violation, `measured.minutes = gap`, `required.minutes = 660` (stock), `assignmentIds = [prev, next]` — the inspector names both cells (the clopen's Sunday close and Monday open).
4. **Consecutive worked days (R_CONSEC_DAYS).** Worked-day set = distinct start days with ≥1 assignment; runs computed over the merged prior-week + current-week calendar; any run `> days` (6 stock) → blocking, `measured.days = runLength`, `required.days = 6`.
5. **Overtime thresholds (R_OT_DAILY / R_OT_WEEKLY — warnings).** Daily worked minutes per start day, weekly = Σ M over the plan week; beyond threshold → warning with measured vs required minutes. In-window days use the reduced daily threshold (rule 7) — and where R_RAMADAN_CAP fires on the same day, the Ramadan finding **supersedes** the OT warning (one finding, named as the Ramadan rule — CP-5.3; never double-billing the same minutes).
6. **Cross-week boundary.** The prior week = the team's latest `published` plan with weekStartsOn strictly before this plan's. Found → `boundaryCheck: 'prior-week'`, and rules 3–4 evaluate across it; not found → `'none-found'` and the inspector states the limitation ("Week-edge check limited: no published prior week found" — 03 CP-2.6). Boundary arithmetic uses the **current plan's** ruleset version (the check guards the new week); the pin fields record the fact.
7. **Ramadan per-day.** `inWindow(day) = startsOn ≤ day ≤ endsOn` (dates, team timezone). Week banner state = week ∩ window ≠ ∅. In-window day: R_RAMADAN_CAP `required = reducedDailyMinutes` (360) — exceeded → blocking; the day's OT threshold becomes 360 (rule-5 supersession). Fully in-window week: weekly threshold/caps use `reducedWeeklyMinutes` (2160). Partial week: pro-rata — `cap = ⌊(reducedWeekly × inDays + standardWeekly × outDays) / 7⌋`; worked example: week 2027-03-08 → ⌊(2160×2 + 2880×5)/7⌋ = 2674. All values derive from the ruleset version pinned on the plan (07a).
8. **Qualification (R_QUALIFICATION).** Per assignment: required = shift's `requiredQualificationIds` filtered to **active** qualifications (deprecated are excluded — checks stop, 07a); missing = required − held → blocking. Structural finding: `measured`/`required` omit numbers; the inspector renders the missing qualification labels by comparing the linked shift/worker entities in the same view — the rule name and the missing label are the row's text.
9. **Unavailability (R_UNAVAILABILITY).** Overlap of the assignment span with any window of kind `absence` or `leave`; overlap > 0 → blocking, `measured.minutes = overlap`. `day-off-preference` NEVER violates — advisory roster-rail mark only (03 CP-1 edge).
10. **Night window (R_NIGHT_WINDOW).** Window wraps midnight (`start > end` legal); overlap of assignment span with the window > 0 → warning per assignment, `measured.minutes = overlap` (a flag for the 150% class — the engine never computes pay).
11. **Absolute daily cap (R_MAX_INCL_OT).** Daily worked minutes (start-day attribution) > minutes (660 KSA / 600 UAE) → blocking, measured vs required.
12. **Coverage shortfall (the gate's other half).** Per shift: assignments < headcount → gate blocker `kind: 'coverage-shortfall'` ("Coverage: Friday dinner requires 4, 3 assigned"). Plan state, NOT a RuleViolation — a fact, not a rule judgment (07b WeekPlanView.gate).
13. **Determinism, recompute, waiver.** Every mutation (`upsertShift`, `removeShift`, `placeAssignment`, `updateAssignment`, `removeAssignment`, `recordExternalSwap`, each applied swap in `importSwapSet`) recomputes ALL rules for the affected week and returns the recomputed `WeekPlanView` (recompute honesty, 07b rule 8). Violation ids derive from a stable hash of `ruleKey + workerId? + assignmentIds` — deterministic, never random. `resolved` happens ONLY by recomputation after an edit; `waived` ONLY via `waiveRuleViolation` (actor + reason + clock timestamp); findings pin `rulesetVersion`, `inRamadanWindow`, `computedAt`. Identical (draft state, roster state, ruleset version) → byte-identical findings — re-running the seed's scan yields the same 4+2, the same ids, forever.
14. **Ruleset sanity (validateRuleset / saveCustomRuleset).** HARD errors (save refused, VALIDATION naming the field): minutes ≤ 0 on any cap/threshold/rest; R_REST_GAP > 1440 (min rest > 24h — 03 CP-5 edge); R_MAX_INCL_OT < R_OT_DAILY threshold (absolute cap below the OT threshold); R_CONSEC_DAYS ∉ [1,7]; night window startMinute = endMinute; Ramadan reducedDailyMinutes ≥ the standard daily OT threshold (a reduction must reduce), reducedDailyMinutes ≤ 0, or reducedWeeklyMinutes < reducedDailyMinutes; weekly-rest days > 6. SOFT issues (listed by `validateRuleset`, save allowed): daily-class cap > weekly/5 (a daily cap above a fifth of the weekly cap is unreachable in a 5-day week — the CP-5.2 sanity class); rest > 720 min while R_WEEKLY_REST is enabled (double-rest policy smell — flagged for the author, not blocked). Stale `baseVersion` → CONFLICT with both payloads.

## 3. Paste & export formats (exact — the boundary artifacts)

**Roster paste (`importRoster` content)** — one worker per line, semicolon-separated:
`code;nameAr;nameEn;roleTitle;weeklyMaxHours[;qualificationCodes]` — 5 required fields, optional 6th = comma-separated codes. Rules: weeklyMaxHours a number in (0, 84]; unknown qualification code → the row is invalid (named — the library is the referent; paste creates only *draft roles*, never qualifications); duplicate worker code → invalid row named; nameAr/nameEn may be identical Latin strings (the messy-roster reality — accepted verbatim, isolated at render); role titles not in the library → worker created + the title listed in `draftRolesCreated` (never dropped). Pacing: determinate "row n of total" at fixed 40ms per 10 rows. Result: `workersCreated`, `invalidRows[]` (line number + reason), `draftRolesCreated[]`.

**Marketplace-compatible export (`exportSchedule` format `'marketplace-compatible'`)** — one line per assignment, comma-separated, fixed header row:
`week_start,day_index,role,start_minute,end_minute,break_minutes,headcount,required_quals,worker_code,worker_name_ar,worker_name_en,assignment_id` — times in minutes-from-midnight, Western numerals; names verbatim at their own script. This is the **declared artifact schema** external systems (shift-swap-marketplace class) ingest — a text handoff, not an integration (08 N1; 12 Q-4).

**Swap-set paste (`importSwapSet` content)** — one agreed swap per line:
`assignment_id;from_worker_code;to_worker_code;agreed_at[;note]`, or the hand-typed shape `from_worker_code;day_index;start_minute;to_worker_code;agreed_at[;note]` (resolved deterministically to the assignment of that worker/day/start in the published week). Validation, in order: line's assignment belongs to another week → VALIDATION naming both week starts, nothing applied; from-worker ≠ current assignee → VALIDATION naming the current assignee; two lines touching the same assignment → earlier line applied, later line skipped and named (partial policy); to-worker inactive → skipped (`worker-inactive`); to-worker lacks the shift's required qualification → **skipped** (`qualification-missing` — the paste path guarantees qualification-matched applications, mirroring the marketplace's own gate; the MANUAL record path is the one that applies an unqualified swap and lets the blocking violation fire — 03 CP-4 edge). Application: assignment.provenance = `external-swap` (from/to/agreedAt/source/note), week → `pending-amendment`, recomputation runs for BOTH workers, new findings carry `introducedBySwapProvenance`. Pacing: determinate per swap, 40ms each. `source: 'change-channel'` without granted consent → PERMISSION in capability language (07b rule 5); paste never requires consent.
