## Typography (P12 — Harmattan + Work Sans)

- **Arabic: Harmattan** (real weights **400 / 700** — the family ships two weights; no synthetic bold, no assumed 600: rtl-rules §3 discipline). A readable-humanist Naskh-tempered face designed for sustained reading at UI sizes — the register for explanation sentences that people must actually read at 8am. Arabic body ≥15px equivalent in detection rows; 16px+ in the digest document; line-height 1.6 (1.8 where tashkeel appears in quoted season names); tracking 0 (token-level, rtl-rules §3 — a build rejection otherwise).
- **Latin: Work Sans** (real weights 400/500/600/700): 500 for table headers and detection-row feed names, 600 for the single H1 per screen, 400 body. Work Sans's grotesque plainness keeps the arithmetic rows calm while the plum carries the identity. Numerals: **Western in both directions** (ledger row; data surface per design-language-map §7): observed values, baselines, σ, timestamps, counts — 0-9 everywhere, tabular-figure settings where the implementation supports it; Arabic-Indic digits never appear in system chrome (storage canonical, display formatted).
- One pairing for reading AND chrome (T3 discipline; no third family; the mono-for-data instinct is adopted as a RULE, not a font — numbers render in Work Sans at tabular settings).
- Bilingual rendering rule: explanation pairs render per-side at their own direction in bidi-isolated containers (rtl-rules §2); metric names authored in either script render at their own direction inside the opposite chrome; the digest document's two language sections flow independently (P23 sibling logic — side-by-side, never interleaved).

## Shape, elevation, iconography, motion

- **Radius B (standard 6–10px)**: detection rows 8px, watch cards 8px, feed chips 6px, digest document panels 10px; chips fully-rounded ONLY where the semantic is a removable filter chip (P08 — declared deviation, recorded here).
- **Elevation: soft-lift**: one diffuse ambient step above raised for floating elements (bulk action bar, page-class banner); the digest document reads as a stack of soft-lift panels — a paper digest, not a glass widget. No flat-line substitutions, no layered stacks (T3 restraint).
- **Icons: duotone** (two-tone set, plum accent + ink base): watch glyph = bell-with-pulse-line, feed glyph = signal-column, detection = flag-on-chart, digest = folded-document, season window = calendar-with-spark, snooze = bell-with-clock, acknowledge = check-in-circle, dismiss = x-in-circle, baseline = dashed-horizon-line, backtest = rewind-clock. Severity marks pair their icon with text labels always (never color alone). No sparkle glyphs anywhere — the narration assist is a bordered chip with the text label "narration" and provenance named (ai-native-patterns §1: no magic affordances).
- **Motion: energetic** (motion-language §1): 150–250ms, standard easing with the single controlled overshoot (≤8% travel) **reserved for success moments — detection arrivals and digest completion — never for errors** (errors arrive; they never bounce). Route changes crossfade ≤180ms; queue rows settle in place; the digest document renders as a settle, never a cascade; series-chart band transitions are opacity-only. Reduced-motion: hard cuts + announcements, identical perceivability by construction (09).
- **T3 signature micro-interaction (exactly one) — "The Explained Arrival"** (03 CP-1.7/CP-2): when a detection enters the console queue (its arrival IS the product's success moment — the watch worked), the row slides 8px along the reading axis and settles with the personality's single ≤8% overshoot (200ms, capped), the explanation chip crossfades observed→baseline in the same window, and the live region announces the arrival politely with the same numbers (motion never carries information alone — the announcement is the information; a11y-baseline §4). Reduced-motion: the row renders instantly; the announcement is unchanged. Nothing else in the product expresses personality beyond the energetic standard set.
