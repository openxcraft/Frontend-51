# 08 — Integration Map: price-rule-engine

Declared non-AI (ai-native-patterns §1): no operation on the adapter (07b) invokes an AI capability, and no abstract need below is required by any core workflow — catalog stand-up, cost refresh, rule authoring, simulation, proposal review, the approval gate, and export all complete with every capability unbound (the 00 success signals are tested against the Mock Adapter's all-off configuration, 07c). Architecture speaks only in abstract capabilities; UI copy says kind, not vendor (credential-contract §2). The product's deliberate stopping point (00): the human approves, the artifact ships, the merchant's own systems apply it — every need below serves that handoff, never an execution loop.

## Capability binding gates (LOOP-7 posture — evaluated at binding time, not now)

- **N1 parse fidelity**: a fixed evaluation set (row-grammar parity, upsert semantics, invalid-row naming, future/back-dated effective dates surviving) must pass before N1 ships active — an import that silently mangles effective dates poisons every downstream simulation (07c rule 1: the snapshot resolves from them).
- **N2 publish fidelity AND governance gates**: (a) integrity at destination — the audit ledger is a governance artifact; partial delivery must surface as typed errors with per-format retry, never silent truncation (async-contract §4); (b) **the approval gate travels with the package** — the channel may deliver only proposals carrying an immutable ApprovalRecord, one human-approved package per delivery action; (c) no event-triggered delivery path may be added at binding time without re-opening the LOOP-10 record with the owner (01's competition-law grounding is the recorded rationale — algorithmic execution is the excluded category, and a scheduled/triggered publish loop would be it in delivery clothing).
- **N3 address hygiene**: consent-scoped recipients only; notifications carry proposal status and artifact expiry, never full row sets (data-minimization per credential-contract §7 — the row data lives behind the approval gate in-app).
- **N4 retention**: the 7-day expiry window is declared at creation, surfaced at export, and renewable; retention of downloaded files is the buyer's business (the same posture as the portfolio's money-document family — invoice-generator-desk Q-13 kinship).

## Degradation map (ai-native-patterns §8 — trivial by declaration, stated for completeness)

| Surface | All capabilities unbound (default v1 state) | Any capability failing mid-session |
|---|---|---|
| Catalog, costs, rules, simulation workspace, proposal review, approval gate | **Full function** — the engine is local deterministic arithmetic (07c rules 1–6); nothing pauses, nothing degrades | Full function — capability failures surface only on their own affordances (file intake, package delivery, outbound notify, artifact serving), typed per the 7-class taxonomy |
| Catalog/cost intake | Paste (the primary path; both grammars) | N1 failure → typed error + paste path offered inline on the import composer |
| Export & handoff | Download the package — the default deliverable | N2 failure → per-format retry + manual download of what delivered; N4 failure → regeneration path offered (deterministic) |
| Notifications | In-app center + return state + activity log | N3 failure → in-app surfaces unchanged |
| Approval chain | In-app gate, immutable records, activity log — governance is never a capability | Unaffected |

Quota ladder (ai-native-patterns §5) applies only to the metered platform operations (simulation runs, export packages — P14, 07b `getUsage`); rule evaluation, margin arithmetic, VAT display, and the gates are never metered and never degrade — there is no AI rung to fall from, and the product must not fabricate one (a "reduced checking" state would be a lie about deterministic arithmetic; a simulation either runs or fails typed).

## Risk flags for the owner

- N2 is the highest-consequence binding and the one this product exists to keep honest: its consent language, its approval-gate gate (b), and the LOOP-10 record in 12 are the three locks; any request to relax "one approved package per delivery action" is a request to become the repricer this product refuses to be (00, 01).
- N1 is the highest-leverage binding (vendor cost sheets are paste-hostile at the buyer's volume); its absence is honestly survivable but caps the cost-refresh cycle at paste-scale — the erosion pain the buyer pays to fix (01 [53]) is served fastest with N1 bound.
- The abstract publish channel never names listing tools, marketplaces, or channels of any vendor: where approved prices land after export is the merchant's systems' business. The marketplace-listing-sync boundary (listings carry prices; this engine owns price rules) stays a text/export handoff at v1 and any live seam is an owner decision recorded in BOTH 12s (LOOP-3, 12 Q-5).
