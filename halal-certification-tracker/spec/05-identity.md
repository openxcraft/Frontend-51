## Typography (P03 — Noto Naskh Arabic + Newsreader)

- **Arabic: Noto Naskh Arabic** (real weights 400/500/600/700 — the variable axis carries the 500/600 steps; no 300/800 exists, and none is simulated, rtl-rules §3). A book-naskh: the register's Arabic reads as documents, not dashboards — the script the body's certificates are actually written in. Body ≥15px equivalent in tables, 16px+ in dossiers.
- **Latin: Newsreader** (weights 400/500/600/700; optical-size axis bound textward). An editorial serif with old-style text figures — the English side of a bilingual certificate tradition. 500 for table headers and certificate numbers; 600 for the single H1 per screen; 400 everywhere body.
- **Numerals: Western** (ledger row; data/finance-grade surface per design-language-map §7): dates, rung offsets, days-to-expiry, certificate and E-numbers all 0-9; Arabic-Indic numerals never appear in system chrome. Newsreader's old-style figures are display-only; tabular lining figures are bound for data columns (`font-variant-numeric: tabular-nums` — a token obligation, not a style choice: register columns must align at any zoom).
- Line-height: Arabic 1.7 body (naskh descenders and stacked marks demand more than the 1.6 floor — tashkeel-bearing ingredient strings reserve headroom), 1.4 headings; Latin 1.5 body / 1.3 headings. Tracking 0 for Arabic everywhere (token-level, rtl-rules §3); Latin may take up to +0.01em at caption sizes only.
- One pairing for reading AND chrome (T3 discipline; no third family; no mono — certificate numbers and E-codes render in Newsreader tabular figures, not a code face; a code face would make the register read as an app, and this register must read as a filing system).
- Bilingual string rule: identity-bearing fields (applicant names, ingredient names, certificate titles) are authored in both locales with per-side direction rendering (P23 sibling logic); Latin ingredient tokens (E-numbers, "INS") inside Arabic prose render in bidi isolation (rtl-rules §2).

## Shape, elevation, iconography, motion

- **Density B (standard, 6–10px)**: register rows 6px, case cards 8px, certificate-document surface 10px; the one declared exception is fully-rounded removable filter chips (P08), recorded here and in 06.
- **Elevation: layered-depth** — stacked surfaces with occlusion. Three layers, bound as tokens: canvas (0.97) → raised panels (0.995 + shadow-1: a soft 0 1px 2px occlusion edge) → overlay documents (white + shadow-2: 0 8px 24px with a 1px Forest Mist occlusion border). The certificate detail's document surface physically sits above its ladder timeline the way an issued certificate sits above its file; the formulation editor's line rows sit on raised, its resolution drawer on overlay. Flat-line is forbidden here (borders do not separate — depth does), and glass is forbidden everywhere.
- **Icons: line-1.5** (thin editorial stroke): ladder glyph = 3-rung ladder; ingredient glyph = leaf-in-flask outline; formulation = branch-list; traceability = three linked nodes; mushbooh = question-in-diamond; audit record = document-with-seal; decision = gavel-outline; certificate = certificate-with-ribbon (thin, never filled); supplier certificate = certificate-with-link. No sparkle glyphs exist anywhere (non-AI declaration, ai-native-patterns §1 — there is nothing to be smart about and the icon set says so by omission).
- **Motion: stately** (motion-language §1): 280–480ms, emphasized decelerate, staggered reveals ≤60ms capped at 5 elements. Route changes crossfade ≤280ms with a single content settle; register rows stagger in on first paint only (≤5 rows, then plain); modal/popover 140ms scale-fade with focus trap and return (a11y-baseline §3). **Signature micro-interaction (the one): the rung settle** — when a renewal rung clears, its marker travels down its ladder rung to the cleared position (≤320ms, emphasized decelerate) and lands as a Halal Leaf check with a state chip; the announcement is polite and the text change is simultaneous (motion never carries the information alone — a11y-baseline §4). Everything else is the standard stately set: issuance renders the certificate document settling into the register (one 360ms settle, no confetti, no bounce — a register does not celebrate, it records).
- Reduced-motion contract (motion-language §5): rung settle collapses to an instant state chip + polite announcement; staggered reveals render simultaneously; route changes hard-cut; the certificate settle becomes a 2-step opacity. Perceivability identical by construction.
