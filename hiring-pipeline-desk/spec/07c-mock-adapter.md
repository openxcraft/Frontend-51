## Deterministic computation rules (the whole rules engine — specified exactly)

1. **Normalization pipeline** (applied to names, evidence text, question text, and search input; ruleset disclosed in-product): strip tashkeel (U+064B–U+065F, U+0670) and tatweel (U+0640); unify alef variants (أ إ آ ٱ → ا); taa marbuta (ة → ه); alif maqsura (ى → ي); Latin: case-fold, trim, collapse internal whitespace. Word count = whitespace-separated token count after trimming punctuation (Arabic and Latin alike).
2. **Template bank** (the assist's deterministic floor): a fixed matrix of competency-class × seniority × language, 3 questions per cell, shipped as seed data. Representative cells (verbatim): communication/mid/ar — ["صف موقفاً اضطررت فيه إلى تبسيط شرح تقني لعميل غير تقني.", "كيف تبدّل سجل كلامك بين الفصحى ولهجة العميل؟ أعطِ مثالاً.", "حدثني عن رسالة اعتذار كتبتها لعميل — ماذا قلت بالضبط؟"] · communication/mid/en — ["Describe a time you simplified a technical explanation for a non-technical customer.", "How do you switch register between formal and colloquial speech? Give an example.", "Tell me about an apology message you wrote to a customer — what exactly did you say?"] · problem-resolution/senior/ar — ["امشِ معي عبر أصعب تصعيد حللته: ما الخطوات بالترتيب؟", "قرار إيقاف خدمة عميل مربح لانتهاز السياسة — كيف تصوغه للفريق؟", "متى آخر مرة عدّلت قرارك بعد معلومة جديدة؟ ماذا غيّرت؟"]. Proposal order is fixed cell order; `count` slices the first N; quota is never consumed in template mode.
3. **Nudge rule N1 — evidence-thin**: evaluated per competency on submit and re-evaluated on every evidence edit of a submitted card: fires iff `rating ∈ {1, 4}` AND `wordCount(evidence) < 15`. Carries the measured word count. Resolution 'addressed' happens only when the re-run on edited evidence no longer matches (recompute, never hand-set).
4. **Nudge rule N2 — trait-language**: fires iff the normalized evidence contains ≥1 token in TRAIT_LEXICON AND 0 tokens in BEHAVIOR_LEXICON (exact token match after the pipeline; both lexicons are fixed seed constants, EN+AR, and their contents are disclosed in-product on the chip detail — ai-native-patterns §7.4 disclosure discipline applied to a non-AI rule). TRAIT_LEXICON (seed): EN {brilliant, charming, aggressive, likable, sharp, polished, impressive, smart, great, strong, amazing, natural} · AR {رائع, رائعة, ذكي, ذكية, لبق, لبقة, محبوب, محبوبة, واثق, واثقة, قوي, قوية, متميز, متميزة, موهوب, موهوبة}. BEHAVIOR_LEXICON (seed): EN {explained, described, walked, built, resolved, handled, asked, answered, proposed, led, missed, failed, delivered, switched, wrote, fixed, escalated, apologized} · AR {شرح, شرحت, وضح, وضحت, وصف, وصفت, بنى, حل, حلت, تعامل, تعاملت, سأل, سألت, أجاب, أجابت, اقترح, اقترحت, قدم, قدمت, كتب, كتبت, أنجز, أنجزت, اعتذر, اعتذرت, صعد, صعدت}. Lexicon entries are stored as surface forms and normalized at comparison time — normalization is applied to BOTH sides (lexicon token and evidence token) before the exact-token match, stated as part of the rule. The card-001 fixture matches: رائعة and its lexicon entry both normalize to رائعه under taa-marbuta unification, so the match holds; conjunction-prefixed evidence tokens (e.g. وأجابت) do NOT match the bare lexicon token أجابت — exact token match means exact, and that is why the fixture's behavior-word check counts zero.
5. **Nudge rule N3 — rating-divergence**: at debrief computation, per competency, over the round's submitted cards: `spread = max(rating) − min(rating)`; fires iff `spread ≥ 2`, listing min, max, and the rating members. Advisory-only — never blocks `recordDecision`; visible with jump links to each side's evidence (03 CP-4.3).
6. **Debrief arithmetic**: competency mean = simple mean of that competency's ratings across the round's submitted cards (2 decimals, Western numerals); overall card score = Σ(competency mean × competency weight) / 100; recommendation tally = counts of the four recommendation values; aggregate withheld (`aggregate` omitted) until allIn. Deterministic re-derivation at any time from card state — the debrief is never authoritative storage (07a).
7. **Debrief gate (allIn)**: every interview of the round with state 'completed' must have a submitted card for each of its interviewerMemberIds ('voided' cards count as resolved — the deactivation edge, named in the activity log). Cancelled and no-show interviews are excluded from the requirement and listed by name in the readiness state.
8. **Anonymized screening (A5)**: iff workspace.anonymizedScreening AND the application's current stage kind ∈ {application, screening} AND session.role ∈ {recruiter, hiring_manager} → displayName = "Candidate #" + the application's per-opening sequence number (createdAt order — stable, deterministic). Owner sees names (audit duty); interviewer seats see names only for their scheduled interviews' candidates; the display rule is disclosed in Settings beside the toggle (a display discipline, never data redaction — names remain in storage and surface at Interview stage).
9. **Independence seal**: `getScorecard(interviewId)` returns the caller's card; another member's cardId → PERMISSION "Scorecards are sealed until you submit yours". `listScorecards` returns sealed rows (names + states) until the caller's own card is submitted, then revealed full cards. `getDebrief` returns aggregate only when allIn (07a). The seal is enforced in the operation layer, before any serialization (07b rule 3).
10. **Double-booking**: two interviews conflict iff they share an interviewer AND `|startA − startB| < min(durationA, durationB)` — checked at `scheduleInterview` and at reschedule via `updateInterview` → CONFLICT naming both interviews.
11. **Import parsing**: rows are `nameLatin | nameArabic | email | phone | source` (empty fields allowed; both name fields empty, or >5 fields → invalid row, named by line number; rows 1..k−1 retained on failure — partial policy). Duplicate = normalized email equal to an existing candidate's (case-folded) or, when Latin name is empty, normalized Arabic name equal → skipped and named, never merged. Valid rows create candidates (and applications at Applied when `openingId` is provided, with the row's source or 'manual').
12. **Seeded clock**: fixed epoch 2026-10-17T09:00:00+03:00, advancing only on declared actions (each mutation +1 simulated minute); artifacts expire at creation + 7 days; the assist quota window is calendar-monthly with reset at 2026-11-01T00:00:00+03:00 (the fixture's resetAt). No Date.now anywhere in computation.

## Behavior (per operation class)

- `createOpening` — copies the workspace stage template (frozen); `openingsCount` < 1 → VALIDATION; stage template reorder input honored at creation only.
- `saveKit` — competencies outside 4–6 → VALIDATION naming the count; weights ≠ 100 → VALIDATION naming the drift ("weights sum to 85 — 15 short"); per-language coverage gaps return as warnings in the coverage view (never block save — scheduling is the hard gate); stale baseVersion → CONFLICT both kept; save bumps kit version; scheduled interviews keep their pinned kitVersion (07a).
- `proposeKitQuestions` — capability unbound (default) → template mode: deterministic bank rows for competency-class × seniority × language, `quotaConsumed: 0`, origin 'template'; capability bound + consented (injectable) → assist mode: proposals origin 'ai-assisted' streamed in fixed order with pacing 80ms/proposal, stop/regenerate honored, mid-run failure (injectable) delivers partials marked `partial`; quota exhausted → RATE_LIMIT with reset time AND the template-mode fallback offered in the same response (`mode: 'template'` with an explicit degraded notice — the ladder, never a wall); `count` outside 1–5 → VALIDATION.
- `scheduleInterview` — the bilingual coverage gate (rule 2's hard teeth): missing AR/EN questions → VALIDATION naming each competency+language pair; interviewer not in interviewer role → PERMISSION; double-booking → CONFLICT naming both; opening paused/closed → VALIDATION naming the status. Success pins kitVersion.
- `submitScorecard` — missing rating on any competency → VALIDATION naming it; empty evidence → VALIDATION naming the competency; missing recommendation → VALIDATION; stale baseVersion → CONFLICT both payloads; success computes N1/N2 per rules (3–4), attaches nudges, seals the card to peers, and appends activity (`scorecard-submitted` + `nudge-fired` per fired nudge).
- `resolveNudge` — 'dismissed' without reason → VALIDATION; 'addressed' re-opens the evidence field; the nudge closes ONLY when the rule re-run on the saved evidence no longer matches (rule 3/4); resolving an already-resolved nudge → CONFLICT showing current state; another member's card nudge → PERMISSION.
- `recordDecision` — outstanding card → VALIDATION naming interview + interviewer; reject/hold without rationale → VALIDATION; hold without reviewOn → VALIDATION; baseDebriefState drift (late card) → CONFLICT, the late card becomes post-decision history; success pins the debrief snapshot and appends.
- `moveApplication` — terminal stage without reason → VALIDATION; stale baseStage → CONFLICT with current stage; anonymization display recomputes per A5 on the returned rows.
- `exportOpeningPackage` — artifacts expire +7 days, regenerable always; partial failure injectable per format (slate / scorecards / ledger) with per-format retry; includeNames carried into the artifact metadata; idempotent re-submit returns the original job.
- `getArtifact` — expired → NOT_FOUND with regenerate (deterministic — identical package from identical state, kit versions pinned).
- `getUsage` — fixed window with seeded counts; quota exhaustion injectable (RATE_LIMIT ladder copy in 11).
