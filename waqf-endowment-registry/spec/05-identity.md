## Typography (P10 — El Messiri + Lora)

- **Latin: Lora** (real weights 400/500/600/700, variable axis; italic available for evidence-note quotes). A warm text serif with old-style tendencies — the English side of a bilingual deed tradition. 500 for table headers and ledger seq numerals; 600 for the single H1 per screen; 400 body.
- **Numerals: Western in all data surfaces; AR-indic (٠-٩) OPTIONAL in Arabic prose contexts only** (the ledger row, exactly): ledger amounts, shares, ratios, dates, seq numbers, and every report figure are Western 0-9 (storage canonical; display formatted — a ledger is a data surface per design-language-map §7, and mixed systems mid-sentence are a defect, copy-voice §1.7). The workspace numerals policy `ar-indic-in-arabic-prose` (default OFF) switches Arabic-Indic rendering in Arabic narrative contexts only — the deed-purpose prose panel and authored bilingual evidence notes — never in tables, never in amounts, never mixed within one sentence (12 Q-5). Lora renders tabular lining figures in data columns (`font-variant-numeric: tabular-nums` — a token obligation: ledger columns must align at any zoom).
- Line-height: Arabic 1.7 body (El Messiri's vertical proportions demand more than the 1.6 floor), 1.4 headings; Latin 1.5 body / 1.3 headings. Tracking 0 for Arabic everywhere (token-level, rtl-rules §3); Latin may take up to +0.01em at caption sizes only.
- One pairing for reading AND chrome (T3 discipline; no third family; no mono — ledger seq numbers and deed references render in Lora tabular figures, not a code face; a code face would make the register read as an app, and this register must read as a filing system).
- Bilingual string rule: identity-bearing fields (deed titles, donor names, beneficiary names, asset names, evidence notes) are authored in both locales with per-side direction rendering (P23 sibling logic); Latin tokens inside Arabic prose (deed numbers, ISO currency codes) render in bidi isolation (rtl-rules §2).

## Shape, elevation, iconography, motion

- **Density B (standard, 6–10px)**: ledger rows 6px, endowment cards 8px, report/deed document surface 10px; the one declared exception is fully-rounded removable filter chips (P08), recorded here and in 06.
- **Elevation: layered-depth** — stacked surfaces with occlusion, three layers bound as tokens: canvas (0.97 warm paper) → raised panels (0.995 + shadow-1: a soft 0 1px 2px occlusion edge) → overlay documents (white + shadow-2: 0 8px 24px with a 1px Mist occlusion border). The transparency report physically sits above the ledger the way a sealed report sits above its file; the ledger's rows sit in the recessed sunken bed (0.92) so the book reads as a book. Flat-line is forbidden here (borders do not separate — depth does), and glass is forbidden everywhere.
- **Icons: line-1.5** (thin editorial stroke): endowment glyph = deed-scroll; asset glyphs = building / coin-stack / share-certificate outlines; beneficiary glyph = person-with-check; share glyph = fraction bar (numerator over denominator, thin rules); ledger glyph = book-with-seq-lines; inflow = arrow-into-book; expense = arrow-out-of-book; reversal = counter-clockwise arrow (symmetric — never flips, rtl-rules §2); distribution = flow-split (one line forking to three); report glyph = document-with-ratio-bar; seal glyph = seal-press (ring + inner mark); delivery = hand-receipt; activity = clock-with-list. No sparkle glyphs exist anywhere (non-AI declaration, ai-native-patterns §1 — the engine is arithmetic and the icon set says so by omission).
- **Motion: stately** (motion-language §1): 280–480ms, emphasized decelerate, staggered reveals ≤60ms capped at 5 elements. Route changes crossfade ≤280ms with a single content settle; registry rows stagger in on first paint only (≤5 rows, then plain); modal/popover 140ms scale-fade with focus trap and return (a11y-baseline §3). **Signature micro-interaction (the one): the seal settle** — when a report is sealed, the seal mark (garnet ring with the gold ring accent) travels to the report header and settles in ≤360ms emphasized decelerate; the ledger pin line ("pinned to seq 214") and the sealed-at timestamp render simultaneously; the announcement is polite and the text change is concurrent (motion never carries the information alone — a11y-baseline §4). Everything else is the standard stately set: a recorded distribution settles its entries into the ledger bed (one 360ms settle, no confetti — a ledger records, it does not celebrate); delivery state changes are text + chip, no motion beyond the standard state transition.
- Reduced-motion contract (motion-language §5): the seal settle collapses to a 2-step opacity + the state chip + polite announcement; staggered reveals render simultaneously; route changes hard-cut; the distribution settle becomes an instant append with the row-count announcement. Perceivability identical by construction.
