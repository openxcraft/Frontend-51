## Typography (P06 — Almarai + Inter)

- **Arabic: Almarai** (real weights 300/400/700/800 — rtl-rules §3 honored, no synthetic bold): 400 body, 700 headings and the single H1 per screen; 300 reserved for large bilingual label-sheet names. Reads as utility Arabic — the register, not the brochure.
- **Latin: Inter** (400/500/600/700): 500 table headers and tags, 400 body, 600 H1. The invisible hand doing registry work.
- **Tabular figures rule**: every numeric column (tags, counts, dates) renders tabular figures (`tnum` where the implementation supports it) — registry columns are scanned vertically, and proportional digits misalign vertical scanning. This adopts the skill's mono-for-data instinct as a RULE, not a third font (see integration record, rejected #4).
- Line-height: Arabic 1.6 / Latin 1.5; tracking 0 for Arabic everywhere (token-level, rtl-rules §3). Asset tags ("AST-0107") are Latin-digit tokens inside possibly-Arabic chrome — bidi-isolated containers, never force-flipped (rtl-rules §2; the tag block carries `dir="ltr"` isolation).
- **Numerals: Western** (ledger row; data/registry surface per design-language-map §7): tags, counts, dates, quantities all 0-9 in both locales. Arabic-Indic numerals never appear in system chrome (storage canonical, display formatted).
- One pairing for reading AND chrome (T3 discipline; no third family; no microcopy exception — both families are legible at table density).

## Shape, elevation, iconography, motion

- **Density B (standard, 6–10px)**: table rows 6px, cards and dialogs 8px, chips fully-rounded exception ONLY for removable filter chips (P08 — declared deviation, recorded here). **Declared deviation #2**: the label-sheet preview's label cells render at true-to-print geometry (square corners, 25/40/60mm proportions) — the preview is a fidelity surface for a physical artifact, not a UI card; physical corners are square.
- **Elevation: flat-line**: hairline steel-tinted borders carry all structure; the registry grid separates by border weight and the canvas→raised surface step (0.97→0.99); the custody timeline encodes chain density in border-inline-start weight. Zero shadows anywhere; no glass, no blur (rejected below).
- **Icons: line-2** (standard-weight outline set, Lucide-class vocabulary converging with the ledger): tag (labels), search, filter, printer (sheet printing), clipboard (sign-off sheets), check-circle (applied/verified), link (chain events), box (locations), users (people), archive (retirement), pen-line (signature), eye (sighting), a **constructed QR glyph** (2×2 modules on the line grid — the skill's CSVs ship no QR row, so the glyph is constructed to the line-2 grid and recorded here). Directional glyphs (custody chain arrows, drill chevrons) flip in RTL; semantically anchored glyphs (QR, tag, printer, eye) never flip (rtl-rules §2). No sparkle, wand, or "smart" glyphs anywhere — declared non-AI product (ai-native-patterns §1).
- **Motion: minimal** (motion-language §1): opacity-only transitions ≤120ms; position changes are instant with a crossfade; route changes hard-cut or ≤120ms crossfade; modals fade+scale 0.98→1.0 in ≤120ms with focus trap and return. The registry never moves data the user is reading. Success moments (label applied, custody signed, retirement recorded) get a state chip + polite announcement — no animation-carried meaning, ever (a11y-baseline §4). Reduced-motion: hard cuts + announcements, identical perceivability by construction (motion-language §5).
