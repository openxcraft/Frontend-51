## B. Original proposals (3 — none exist as a composition in current workforce products; SME-K)

### B1 — The Fairness Reveal (offer-detail layout + ladder reveal cascade; original interaction #1, referenced by 03 CP-2.3 and 05)

**Layout proposal (S3 OFFER DETAIL, mobile ≥360px, RTL-first).** The sheet stacks in order of decision weight, bottom-anchored thumb reach last: (1) **Shift facts strip** — site label (bidi-isolated), time range in Western numerals, break minutes, required qualifications as duotone badges; (2) **requester note card** on copper.tint (≤140 chars, bidi-isolated render); (3) **EligibilityPanel** — green/amber/red states carried by heading text, never color alone (09); the amber state names the exact rule and hours math ("قاعدة واحدة في خطر: يترك لك 9 ساعات راحة قبل صباح السبت — والحد 11." — first clause of 11 §D4 amber); (4) **FairnessLadder rank preview** — the current queue as an ordered list of candidate rows with RationaleChips (seniority band, swap balance, rest compliance, recency — composite score de-emphasized into the drill, 03 CP-3.1); the viewer's OWN row is anchored by a copper edge-bar along the inline-start edge (reading-axis cue); (5) request CTA, with the policy-sheet link ("كيف تُرتَّب التبديلات — القاعدة الإصدار {version}", 11 §D5) directly beneath the ladder — inspectability is one tap from every rank (04 IA decision).

**Motion choreography.** On sheet open: facts strip renders immediately (embedded data, no skeleton dance — P02 honesty); ladder rows cascade with stagger ≤60ms capped at 5 rows, then simultaneous (05 tier-1 obligations — the cascade is 5 rows max); each row's chips ink in 60ms after its row settles; the copper own-row edge-bar draws LAST as a single 120ms scale-X from the reading-axis origin — the eye ends on "where do I stand". Rank deltas NEVER re-animate the list under the user's finger: rows patch in place via subscribeSwapEvents (10), announced politely on focus only (09). Rationale drill expands as a ≤150ms height disclosure (arrive-don't-bounce).

**A11y implications.** Ladder is an `ol` — rank IS list position; ordinal announced on row focus ("المرتبة 2 من 5", never on every change); chips are text+icon (never color-only); drill is a disclosure with `aria-expanded` (06 FairnessLadder); the copper edge-bar duplicates its meaning in text — the own row's described-by carries the rank-ordinal register already pinned in 11 §D3 ("المرتبة 2 من 5" family), so the bar is decoration, not information. **Reduced motion:** all rows render simultaneously, rank carried as text; the cascade collapses entirely (06). Loading state copy: "ترتيب القائمة — الحساب سريع؛ وسيعرض كل رقم سببه." (11 §B).

**Mood anchor.** A queue you can read at arm's length — chalkboard order, not casino scramble.

### B2 — The Swap Handshake (signature confirmation choreography; original interaction #2, referenced by 03 CP-3.3, 05, 06)

**Layout + choreography (worker surface; fires once, on the confirm event only — never on re-renders, 10).** When a match is confirmed (accept → supervisor-approved → confirmed): the offering worker's shift card and the incoming worker's card **converge along the reading axis** (inline-start↔inline-end, mirrored in RTL) over 200ms standard easing; a **single copper weld line** (accent.primary #B85E31, ≥3:1 as a UI component on paper — never body text) flashes the joint for 120ms with the product's ONE controlled overshoot ≤8% (the energetic personality's reserved success overshoot, motion-language §1); the welded pair then settles (≤180ms, arrive-don't-bounce — no shake, no bounce loop) and **collapses into the confirmed-coverage card** carrying the WeldMarkBadge (⊨ double-line + "تم تأكيد التبديل — التغطية مؤكدة" / "Swap confirmed — coverage is locked", 11 §E) and the toast pair's second line ("{name} takes your Thursday evening" / "يأخذ {name} مساء خميسك", 11 §F). The rest of the screen does not move — the Handshake is a focal event, not a page-wide party (no confetti ever; 02 voice derivation). The weld-mark is semantically reserved for confirmed coverage only (06 WeldMarkBadge) — the glyph itself is part of the choreography's meaning: this is now real, recorded coverage.

**A11y implications.** Assertive-once live-region announcement AT the weld moment ("تم تأكيد التبديل — التغطية مؤكدة" + shift facts), then a polite summary (09 announcement schedule); motion is never the only carrier — the state chip + weld-mark badge carry the same fact statically for later review (06 SwapHandshake; a11y-baseline §4). **Reduced motion:** the pair crossfades in place to the state chip; the overshoot collapses to zero (05 signature-moment contract; motion-language §5). On the console leg, the equivalent moment is a row-state change + "تمت الموافقة — أُخطر العاملان" / "Approved — both workers notified" (11 §F) — the console never replays the worker celebration (calm accountability).

**Mood anchor.** Two obligations becoming one covered reality — a weld, not a firework.

### B3 — The Rest Ribbon draw (blackout time-ribbon; original interaction #3, referenced by 03 CP-2.2, 05, 06, 07b EligibilityReport)

**Layout proposal.** A horizontal **48-hour time ribbon** (SVG+text composite, 06 RestRibbon) centered on the target shift: the worker's adjacent shifts render as solid bands; the protected minimum-rest windows render as **hatched no-go bands** (duotone graphite hatching — texture, not hue, carries "blocked" so the band reads identically for color-vision differences and in print); a violation renders a **named flag** pinned above the band edge — an alert region carrying the rule's plain-language string from the contract ("سيترك لك هذا التبديل 7 ساعات راحة قبل ليلة الجمعة — والحد الأدنى 11." — first clause of 11 §C VALIDATION-blackout). Hour ticks every 6h in Western numerals; the target shift's band is copper.tint with a copper edge. In RTL the time axis runs inline-end → inline-start with labels preserved (09 verification matrix — the ribbon's direction mirrors, its math never does). Inputs are contract data only: `restHoursBefore` / `restHoursAfter` / `weeklyHoursIfAccepted` from EligibilityReport (07b) — the ribbon visualizes, the engine computes; it never does its own math.

**Motion choreography.** On panel render: bands wipe outward from the target shift in both directions simultaneously (≤150ms each), then the no-go hatching fills (≤80ms), then the violation flag settles (≤100ms) — the draw order teaches causality in reading order: the shift, the rest it would leave, the rule it breaks. A violation flag NEVER pulses or loops (no ambient animation — motion-language §6); it arrives once and stays.

**A11y implications.** The ribbon is a focusable figure with an aria-describedby description that states the rest hours in words ("الراحة عند القبول: 9 ساعة — الحد الأدنى للقاعدة 11", 11 §D1 rest-compliance template); every band carries a text label; the violation flag is an alert region with the rule name (06); tap targets per shift segment ≥44px; the ribbon is decorative WITHIN a panel that already announced its state by heading text (EligibilityPanel, 09) — zoom to 400% reflows the ribbon to a vertical stack with identical labels (09 reflow contract). **Reduced motion:** all bands render at final state, draw skipped, labels identical (06).

**Mood anchor.** A tape measure across the night — the rule drawn where the hours actually are.
