## Deterministic computation rules (the whole engine — non-AI, specified exactly)

1. **Metric-shape normalization**: a line item's `day` = spendDate when metricShape = spend-date; = reportDate-day-attribution otherwise, where aggregate cadences (weekly/monthly report-date lines) attribute their amount **evenly across the covered days** (weekly line ÷ 7 on each covered day; monthly line ÷ days-in-month) — the declared split convention for aggregate cadences (honest gap 2: declared policy, not a research-cited fact). conn-agency's monthly lines thus land as even daily attributions; the WF26 fixture's SAR 101,500 attributes as 101,500/30 ≈ SAR 3,383.33/day across September.
2. **FX conversion**: basis = connection override, else workspace policy. daily-rate: use the (from→to) row DATED on the line item's normalized day; monthly-average: use that day's month row; native currency = reporting currency: state `native` (rate 1, no rate row). Missing row → state `rate-unavailable` (amount absent — never zero; day flagged per rule 6). Receipt pins (nativeAmount, rate, rateId, basis, policyVersion, reportingCurrency, reportingAmount = nativeAmount × rate, rounded HALF_UP to 2 minor units — SAR/AED/USD all 2-decimal currencies per the ISO 4217 convention, Source 10).
3. **Totals**: snapshot totals are the sum of NormalizedSpendRecord.amountReporting grouped per connection/day; records group by (connection, campaignRef, day) with receipts per member line item. Same-currency rows never round-trip through a rate.
4. **Overlap detection** (per consolidation, over ALL line-item pairs across DIFFERENT connections): candidates = pairs whose normalized externalKeys are equal AND normalized days are equal AND BOTH converted amounts are present. `convertedDelta = |a − b|`; `withinEpsilon = convertedDelta ≤ epsilon × max(a, b)`; findings are created only for withinEpsilon pairs. `score = 1 − convertedDelta / (epsilon × max(a, b))` (clipped to [0,1] — 1.0 = exact match). Multi-member clusters group by (externalKey, day). Ordering: score DESC, then clusterKey lexicographic ASC, then lineItemId pair ASC — fully deterministic. Resolution effects (next consolidation): keep-first → the record carries the higher-priority connection's amount (`dedupeState: kept-first`, both line items referenced); split → amounts × (1−portion) and × portion respectively; both-counted → two records, one re-keyed with a generated suffixed key; the excluded/other member stays queryable as a line item — totals never lose money silently (07a state obligation).
5. **Re-check on policy change**: a new consolidation under a changed epsilon or revised amounts recomputes findings; a resolution whose finding no longer exists transitions to `archived` (kept, shown archived — never orphaned); a finding whose evidence moved outside the new epsilon re-opens with the recomputed score.
6. **Overlay computation**: occurrence windows per rule 8; control window = the equal-length window ending the day before window start. `meanDaily(window) = Σ amountReporting over covered days ÷ covered-day count`, EXCLUDING rate-unavailable days (each ratio's `excludedDays` names them; a window with zero covered days → VALIDATION — no honest ratio exists). `liftRatio = meanDailyWindow / meanDailyControl` (3 significant figures at display); `likeForLikeDelta` = this occurrence's meanDaily vs the same moment's PRIOR occurrence's meanDaily (absolute + pct). Control windows overlapping other active moments set `controlConfoundedBy` (honesty flag — e.g. Ramadan 1447's control window 2026-01-19→2026-02-17 is clean; Eid al-Fitr 1447's control window overlaps Ramadan's last days → flagged).
7. **Pacing**: `linearPaceToDate = amount × coveredDays / totalDays`; `variancePct = (spentToDate − linearPaceToDate) / linearPaceToDate × 100`; state: over-pace if variance > +threshold, under-pace if < −threshold, else on-pace. spentToDate excludes rate-unavailable days (named). Partial coverage flagged when coveredDays < totalDays — never extrapolated.
8. **Anchor rules & occurrence matching**: gregorian-fixed → the date in each year in window; movable-gregorian `friday-following-fourth-thursday-nov` → the Friday after the fourth Thursday of November (2024-11-29, 2025-11-28, 2026-11-27), window = that Friday + (lengthDays − 1); hijri-anchored → the seeded Umm al-Qura presentation table (disclosed per moment; tabular fallback declared in 12 Q-7), occurrences enumerated by Hijri year — **prior-occurrence matching is by Hijri year sequence (1447's prior is 1446), NEVER by Gregorian date proximity**; a Gregorian-lookalike comparison request has no adapter representation (07b rule 10). Validation: hijriMonth ∈ 1–12, hijriDay ∈ 1–30, lengthDays ∈ 1–60; movable rules resolve to exactly one date per year or the save is refused with the rule named.
9. **Consolidation run**: reads ALL line items in window (superseded rows excluded — their active revisions included), applies rules 1–4 under pinned (policy version, connection versions, rate-table version), writes a NEW immutable snapshot version, folds applicable resolutions (`snapshotVersionApplied`), recomputes overlap findings per rule 5, sets health flags (open overlaps, late-cadence connections by reportDate vs cadence expectation, revisionsApplied = revision batches folded vs previous version, rateUnavailableDays). Pacing: rule 7 at read. The same inputs re-run → byte-identical snapshot content (the determinism oracle).

## Behavior (per operation class)

- `createChannelConnection` — duplicate dedupePriority among active connections → VALIDATION naming both; unknown currency code (not 3 uppercase letters / not in the active list) → VALIDATION. `updateChannelConnection` — stale baseVersion → CONFLICT both payloads; status→revoked appends the activity entry and degrades freshness surfaces explicitly (08).
- `verifyChannelConnection` — exercises the declared read round-trip: for paste-only connections returns state `failed` with evidence "no capability bound — paste path needs no verification" (honest: verification is for bound capabilities, credential-contract §7); for the two bound connections returns `active` with the round-trip named.
- `importSpendLines` (paste) — row format: `spendDate, externalKey, campaignRef, nativeAmount, nativeCurrency, reportDate`; malformed rows named in `invalidRows` with prior rows retained (partial); same (connection, externalKey, spendDate) as an existing row → supersede (revision + 1, `supersededByLineItemId` set); currency change on a same-key row → VALIDATION (rule: a revision is same-currency). channel-pull without granted consent → PERMISSION (capability language). Job pacing: determinate "n of total" at fixed 40ms per 10 rows.
- `runConsolidation` — implements rules 1–5 + 9; result carries `mode: 'deterministic'`, exact counts, and the overlapsResolvedFolded count; re-running produces identical snapshot content (test oracle); pacing determinate per record at 40ms/100 records.
- `listSpendLines` / `listOverlapFindings` / `listSnapshots` / `listHolidayMoments` / `listBudgetLines` / `listChannelConnections` — cursor pages ≤ 100; filters and sorts exactly per 07b; normalized bilingual search applies the rtl-rules §4 ruleset (alef/hamza, taa marbuta/heh, yaa/alif maqsura, tashkeel-stripped) and the applied ruleset is disclosed in the search panel (ai-native-patterns §7.4 — a non-AI product still discloses its matching rules).
- `resolveOverlap` — resolution without reason → VALIDATION; split without splitPortion ∈ (0,1) → VALIDATION; already-resolved → CONFLICT current state shown; effect applies at next consolidation (rule 4).
- `updateNormalizationPolicy` — epsilon outside (0, 0.10] or threshold outside (0, 50] → VALIDATION; stale baseVersion → CONFLICT; policy edit re-versions and the NEXT consolidation recomputes (never silent — the UI states the recompute side-effect, 03 CP-3.5).
- `getFxRateTable` — returns rows + disclosure + `missingPairs` for active-connection pairs with no covering rows; rate rows entered via a bound rate source require the explicit accept (source `accepted-proposal`) — the mock seeds one pending proposal row to exercise the accept step (P15 on data).
- `saveHolidayMoment` — anchor validation per rule 8; stale baseVersion → CONFLICT; save re-versions and `nextOccurrences` preview recomputes; name parity warning fires when nameEn/nameAr lengths diverge >40% (band labels are space-constrained — P23 length-parity discipline).
- `saveBudgetLine` — amount currency ≠ SAR → VALIDATION (reporting-currency rule); closed-line edit without amendment reason → VALIDATION; closed-line edit with reason → appends an amendment entry, the line's amounts never mutate.
- `getOverlayComparison` — rule 6; occurrenceLabel must name a real occurrence in window → else NOT_FOUND with the available occurrences listed; zero covered days → VALIDATION.
- `getPacing` — rule 7; budget line with no covered days in the snapshot window → VALIDATION with an honest empty read named.
- `exportReportPack` — artifacts expire at creation + 7 days; `regenerable: true` always; pins snapshot version and names newer versions at handoff; partial failure injectable per format; idempotent re-submit returns the original job.
- `getArtifact` — expired → NOT_FOUND with regenerate; regeneration is deterministic from the pinned snapshot (byte-identical — the oracle).
- `getUsage` — fixed window with seeded consolidation/export counts; quota exhaustion injectable (RATE_LIMIT ladder copy in 11).
