## Deterministic selection heuristics — the RULES (non-AI, specified exactly)

`findHighlights` is a fixed scoring pipeline over the transcript's segments. No model, no randomness, no external calls. Identical input → identical output, always.

1. **Keyword density**: declared keyword sets (default set embedded in the seed per episode language; operator `focusKeywordSets` override merges). For a sliding window of W=45 segments, `density = weightedKeywordHits / segmentCount`, normalized 0–1 against the transcript's max window. Candidate windows are maximal spans where density ≥ 0.6. ES-1's fixed table: windows at segments 0–44 (intro hook), 118–162 (education/AI), 236–289 (assessment), 355–401 (teachers), 471–519 (policy), 590–641 (jobs), 658–712 (closing advice) → 7 candidates.
2. **Speech-pause boundaries**: inter-segment gaps ≥ 700ms (from segment timings; untimed transcripts use sentence-terminal punctuation as the fallback boundary signal, disclosed in the rationale) are pause marks; `pauseSupport` = fraction of the candidate's window edges coinciding with a pause mark (within ±1 segment). ES-1's fixed pause table: pauses at 117, 163, 235, 290, 354, 402, 470, 520, 589, 642, 657, 713.
3. **Hook patterns**: the first segment of a candidate window is tested against rules: (a) interrogative — text begins with a question particle (Arabic: هل/ما/لماذا/كيف; English: what/why/how) or ends with "؟"/"?"; (b) imperative opener — begins with an imperative verb form (declared list); (c) numbered claim — begins with a numeral followed by a noun ("3 أخطاء…", "5 things…"). `hookPattern` = 1.0 / 0.6 / 0.8 respectively, else 0.
4. **Composite + rationale**: `score = 0.5·keywordDensity + 0.3·pauseSupport + 0.2·hookPattern`; candidates rank by score; rationale strings are table-assembled, bilingual per session locale: "كثافة كلمات مفتاحية عالية عند المقاطع 118–162، وحدودها محاذاة لسكتتين" / "High keyword density at segments 118–162, edges aligned to two pauses"; matched keywords are disclosed in `matchedKeywords` (ai-native-patterns §7.4 disclosure analog — the normalization/kind of match is always visible).
5. **Duration filter**: candidates outside [minDurationSec, maxDurationSec] (defaults 15/90) are dropped — the zero-candidate path returns an honest empty with the threshold statement.

## Behavior (deterministic)

- **importTranscript**: format detection table-driven and REPORTED in the job result (never silent); pasted timestamped text parses at a fixed 90ms/100-segments cadence; overlapping cues → VALIDATION with both cue line numbers; `untimed-plain` → job parks in `awaiting-input` until a duration declaration (or a media reference with probed duration) resumes it. Re-import over a source WITH clips → clip boundaries re-anchor by timecode match within ±2s; unmatched clips flagged `pending-timing`-style lint, never dropped (CP-1 edge).
- **findHighlights**: pure table lookup + the rule pipeline above; the seed's candidate tables are fixed per transcript; synchronous (no Job, no quota — 07b rule 2). Zero candidates for ES-5's untimed sample when duration-filtered (threshold copy fixture).
- **Clips**: create/update validate segment ranges and offsets against the anchor segment's duration (violations → VALIDATION with the legal range in `details`); boundary moves re-derive timecodes AND re-run the spec lint; `deleteClip` returns the snapshot for undo; stale baseRevision → CONFLICT with both payloads.
- **setClipBurnInSpec**: lint is a fixed function: reading-speed per line = chars / display window vs the per-script gate (defaults 14 cps ar / 17 cps en — declared product defaults, no external benchmark claimed, flagged in 12 Q-7); safe-zone check is geometric against the preset's band (tiktok-class ≈ 14% top / 35% bottom / 6% sides; shorts/reels variants per the 07c preset table); line-overflow checks per-script char budgets with the joined-word no-break rule; bidi-reorder-risk fires on mixed-direction runs under `dominant-script` and clears under `isolate-runs` (the ES-2 proof); tashkeel-clipping-risk fires when `tashkeelMode:'on'` meets a style whose line-height token cannot host marks.
- **exportClips**: render mode paces deterministically per clip (140ms/clip with determinate "الكليب n من m" progress); render minutes consumed from the fixed window (4/5 used in the seed — the 80% warn fixture); at 0 → RATE_LIMIT before any work with reset time; recipe mode produces REAL deterministic files: SRT + VTT sidecars (bilingual per clip text, Western numerals, per-line direction policy), a boundary timecode sheet, and the burn-in spec manifest — zero render minutes. Idempotency keys collapse double-submits; partial failure injectable per clip (fail clip 3 once); warnings carried onto the manifest verbatim.
- **Credentials**: `verifyCredential` performs a simulated real round-trip (two-step state transition unverified→active, 200ms); expired notification-channel credential → job completions skip the channel and surface on return state only (the degraded path is provable in one fixture); grant mismatch → PERMISSION.
- **Usage**: fixed calendar-month window; render minutes decrement per rendered clip duration; warn-at-80% is UI-side via `getUsage` (P14).

## Failure injection

`MockConfig { latencyMs: number; errorRate: 0 | 1; errorCode: ErrorCode; failJobOnce: JobKind | null; failClipOnce: string | null; dropAtJobPercent: number | null }`. `errorRate` is 0 or 1 only (determinism — no probabilistic branches); `failJobOnce` fails exactly one job of the kind then auto-clears; `failClipOnce` fails exactly one clip within an export batch (partial-results retention proof); `dropAtJobPercent` severs a running job mid-way to exercise reconciliation and partial-result retention. Fixed correlationIds `scc-corr-0001`…, allocated sequentially per emitted error.
