# 07c — Mock Adapter: marketplace-listing-sync

In-memory, deterministic, zero external dependencies. Implements `MarketplaceListingAdapterV1` (07b) over the entities of 07a. No randomness, no network, no timers beyond the declared cadences; identical call sequences produce identical states (the determinism contract is the mock's own test oracle). The conditionally-AI suggestion surface is **simulated deterministically** (rule 3): the mock computes candidate pairings and confidences by exact formula, labels every suggestion `assist-simulated`, and the capability toggles on/off by configuration — never by model magic.

## Deterministic computation rules (the whole engine — non-AI, specified exactly)

1. **Normalization pipeline** (applied to search input and to nothing that stores): strip tashkeel (U+064B–U+065F, U+0670) and tatweel (U+0640); unify alef variants (أ إ آ ٱ → ا); taa marbuta (ة → ه); alif maqsura (ى → ي); Latin: case-fold, trim, collapse whitespace. Applied ruleset disclosed in the search panel (ai-native-patterns §7.4 — a non-AI product still discloses its matching rules). Numeral-form folding NOT applied: "1000" never matches "١٠٠٠" (rtl-rules §3 — parsing semantics are never changed by display).
2. **Mapping resolution** (the mapped preview's values — pure function of master version + map version + overrides): for each MappingRow, resolve the source value (locale variant selected per `localeVariant`; numeric/image fields take `none`); apply transform — `none`: verbatim; `truncate-word-boundary maxLength`: cut at the LAST word boundary at-or-before maxLength (never mid-word; Arabic words break at spaces — rtl-rules §4; if the first word alone exceeds maxLength, cut at maxLength and mark the row's transform note "first word longer than ceiling"); `template`: compose over declared fields ("{brand} {title}" → resolved bilingual values joined in template order, bidi-isolated at render). Overrides REPLACE the mapped value for their attribute key and set `overridden: true` — never merged.
3. **Suggestion confidence (the simulated capability — exact formula, disclosed as `formulaNote`)**: for candidate (masterField f, localeVariant v, channelAttributeKey a): `overlap = |normalizedTokens(label(f) + localeName(v)) ∩ normalizedTokens(label(a))| ÷ |union|` (Jaccard over tokenized labels, 2 decimals); `constraintBonus = 0.10` if the attribute's maxLength equals the rule pack's ceiling for that kind (catalog-constraint coherence); `requiredBonus = 0.08` if the attribute is required and unmapped; `confidence = max(0.05, min(0.98, round(overlap + constraintBonus + requiredBonus, 2)))` — candidates below the 0.05 floor after bonuses are not listed. The seeded fixtures derive exactly: S-001 = 0.60 + 0.10 + 0.08 = **0.78**; S-002 = 0.43 + 0.08 = **0.51**; S-003 = 0.00 → floored **0.05**. The 00 DoD's "accept a high-confidence suggestion, edit a medium one, reject a wrong one" maps to 0.78 / 0.51 / 0.05.
4. **Compliance evaluation** (per listing, per rule in the pinned rule-pack version — pure arithmetic over the resolved mapped preview):
   - title-length / description-length: `measured = character count of the resolved value` (code points, Western numerals at display); `measured > max` → blocker; `measured ≥ 0.9 × max AND ≤ max` → warning (near-ceiling band); per-locale rules evaluate the locale-specific attribute value.
   - bullet-count / bullet-length: resolved bullets array — count outside [min, max] → warning; per-bullet length outside [min, max] → warning.
   - required-attribute: resolved value for a required attribute is empty/absent → blocker (measured = the attribute key; limit = "required").
   - image-count: resolved image-list length `< min` → blocker; `< recommended` (min 1, recommended 3) → warning.
   - forbidden-characters: any char of the declared set present in the resolved title → blocker (measured = the matched chars; limit = the set).
   - bilingual-parity: for channels with `both-required`: for each paired attribute group, either locale variant empty while the other is non-empty → blocker naming the locale (measured = "ar missing" / "en missing").
5. **Readiness derivation**: listing `blocked` iff ≥1 open blocker finding; `ready-with-warnings` iff zero blockers and ≥1 open warning; `ready` iff zero blockers, zero open warnings (acknowledged warnings do not block); `draft` before first check. Warnings acknowledge-only; blockers resolve by data edit (`edit-resolved` recomputed by rule 4), rule change (`rule-change-resolved` recomputed after pack edit), or never by hand.
6. **Recompute triggers**: full check (Job) recomputes all findings for the scoped listings; `updateMasterProduct`/`updateListing` recompute affected listings' findings live (simulated ≤60ms; UI budget ≤80ms per 10) — `edit-resolved` transitions happen ONLY here; `resolveComplianceFinding` never alters computed fields, it records `acknowledge` resolutions (audit chain). Acknowledgment persistence: keyed by (listingId, ruleId) — a re-run regenerates the finding and re-attaches standing acknowledgments by key (CP-3 recovery guarantee).
7. **Staleness derivation** (computed on every read, never stored): `stale = checkedAgainst.masterVersion < product.version OR checkedAgainst.fieldMapVersion < map.version OR checkedAgainst.rulePackVersion < pack.version`. Published listings compare `publishedAgainst` additionally for the CP-5 master-diff view. A listing whose master product is deleted → NOT derived-stale but terminal: the mock returns the listing with a `master-missing` detail and the UI offers unpublish-or-archive (never auto-delete).
8. **Bulk staleness scoping**: `bulkUpdateMasterFields(field)` stales only listings whose channel's field map contains a row reading that field (computed from the mapping — the job-006 fixture: 6 products updated, 4 listings stale because 2 products' channels at that moment did not map stock; blanket-staling is a contract violation).
9. **Publish evaluation**: per listing in the requested set — state must be `ready` or `ready-with-warnings` AND `stale = false` AND not paused; else `skipped` with the reason. Attempted listings: the bound channel-publish capability is simulated with the **rejection table** (fixed): listing DN-1012 (brand containing "Nayif Ateeq & Co." — ampersand in brand) → rejection `{code: 'ERR-8512', message: 'Item rejected: brand field contains unsupported characters', taxonomyCode: 'VALIDATION'}` verbatim; all other attempted listings publish and write pins. Injection config can reject any Nth attempt for the RATE_LIMIT/NETWORK fixtures.
10. **Export evaluation**: ready + ready-with-warnings listings of the channel compose the file; blocked/stale excluded and counted (`excludedBlocked`); acknowledged warnings annotated per listing; `verdictsCarried: true` always. Artifacts expire at creation + 7 days; regenerable deterministically from listing state.
11. **Seeded clock**: starts 2026-11-09T10:15+03:00; every job advances it by the job's simulated duration at the declared cadence (import 40ms per 10 products; check 40ms per listing; publish 120ms per listing; export 60ms per listing); timestamps in findings/activity derive from this clock only — no Date.now anywhere.

## Behavior (per operation class)

- `createChannel` — archetype seeds the attribute catalog + rule pack verbatim from the tables above (v1); `localeRequirement` mismatch with archetype defaults allowed (owner choice, findings re-evaluate); name collision within workspace → VALIDATION naming both.
- `importCatalog` (paste) — block format: `sku | title-ar | title-en | desc-ar | desc-en | brand-en | images (comma URLs, first = main) | price | stock` one block per product, blank line separated. Missing title-en or title-ar imports as-is (bilingual gap counted — the parity rule flags at check); unknown fields → named invalid block; SKU exists → product UPDATED (merge policy: non-empty pasted values overwrite, empty pasted values keep existing); job pacing determinate "n of 24". `catalog-intake-capability` without consent → PERMISSION (capability language).
- `updateMasterProduct` — stale `baseVersion` → CONFLICT both kept; price/stock edits are plain data (no rule engine — PERMISSION never, but any *rule-like* intent is out of contract by design); returned view carries recomputed findings for affected listings (rule 6) and the staleListings count.
- `bulkUpdateMasterFields` — per-row VALIDATION named (non-numeric stock, negative price); valid rows proceed; staleness per rule 8.
- `saveFieldMap` — two rows targeting the same `channelAttributeKey` → VALIDATION naming both rows; transform on numeric/image source → VALIDATION; template referencing a non-declared field → VALIDATION; stale `baseVersion` → CONFLICT; success bumps map version and returns `staleListings` count honestly.
- `suggestFieldMappings` — `assistEnabled = false` (config) or capability unbound → PERMISSION with manual-editor copy reference (11 A); RATE_LIMIT after the quota fixture (20 suggestions/window); candidates computed by rule 3 over the unmapped-required scope only.
- `resolveMappingSuggestion` — `edited-accept` without `editedRow` → VALIDATION; resolved-again → CONFLICT; accepted rows stage into the draft map (visible via `getFieldMap` with `diagnostics` noting staged rows — save still required).
- `runComplianceCheck` — recomputes per rules 4–6; result carries `mode: 'deterministic'` and exact counts; re-running produces identical findings from identical state (test oracle); pacing determinate per listing.
- `resolveComplianceFinding` — `acknowledge` on a blocker-severity finding → VALIDATION (the ladder is the point); missing reason → VALIDATION; already resolved → CONFLICT current state shown.
- `createListing` / `bulkCreateListings` — duplicate (channelId, masterProductId) → skipped-and-named `already-listed` (VALIDATION for the single create); archived product → skipped `archived`; `confirmCount` drift → CONFLICT with recounted set.
- `updateListing` — override for a non-catalog attribute key → VALIDATION; stale `baseUpdatedAt` → CONFLICT both kept.
- `setListingPaused` — paused listings are skipped by publish with reason `paused`; unpausing re-derives staleness honestly (rule 7).
- `deleteListing` — requires `confirm.publishedCount` matching the live history count → else VALIDATION; deletion is logged with the publish-history summary in the activity detail.
- `publishListings` — capability unbound (ch-003 default) → PERMISSION with the export path offered inline; per rule 9 with the fixed rejection table; idempotent re-submit returns the original job (same idempotencyKey).
- `exportChannelFile` — per rule 10; `getArtifact` expired → NOT_FOUND with regenerate; `regenerable: true` always.
- `getUsage` — fixed window with seeded counts (checks 6, publishes 3, exports 1, suggestions 2); quota exhaustion injectable (RATE_LIMIT ladder copy in 11).
