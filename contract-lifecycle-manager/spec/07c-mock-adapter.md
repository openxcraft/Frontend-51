## Deterministic computation rules (EXACT — formulas, not vibes)

- **Fixed clock**: 2026-11-04T10:00:00+04:00. All date arithmetic is whole-day integer math against this instant; no wall-clock reads, ever.
- **Urgency zone** (per obligation, at read): with due date D and clock date T = 2026-11-04: `overdue` iff D < T · `imminent` iff T ≤ D ≤ T+7 · `approaching` iff T+7 < D ≤ T+30 · `later` iff D > T+30. Overdue magnitude = T − D in days (seed assertion: O-8 → overdue 20 days; O-S2 → overdue 2 days).
- **Reminder schedule** (derived, per OPEN obligation on an ACTIVE contract): with lead days L1 = leadOverride.firstLeadDays ?? 30 and L2 = leadOverride.finalLeadDays ?? 7, entries fire at `D−L1` (first-lead), `D−L2` (final-lead), `D` (due), then one `overdue-daily` entry per day from D+1 through T (bounded by the clock — no future speculation). listReminders filters to the requested [from,to] window; each entry's zone recomputes by the same zone formula on its fireDate. Dormant rule: obligations on non-active contracts (draft/in-review/awaiting-execution) compute NO reminder entries and render zone "not yet scheduled" — activation is what turns the schedule on (CP-4.6).
- **Recurring next-due**: `nextDue = anchor + ⌈max(0, T − anchor) / interval⌉ × interval` (integer days; if T < anchor, nextDue = anchor). A completion event sets the working anchor to the completion date, and nextDue recomputes from it (deterministic: seed O-2 anchor 2026-08-17 + 90d step → nextDue 2026-11-15; seed O-10 anchor 2026-10-06 + 30d step → nextDue 2026-11-05).
- **Derived lifecycle** (stored active only): with current term end E: `expiring-soon` iff 0 < E − T ≤ 60 · `expired` iff E < T. Otherwise null. (Seed assertions: C-3 → expiring-soon 41d; C-1 → null at 88d.)
- **Notice deadline** (autoRenew contracts only): `N = E − noticeWindowDays`; window-open iff T ≥ N; `daysToNoticeDeadline = N − T`; missed-window display state iff T > N. (Seed assertions: C-1 N = 2026-12-02, 28 days out; C-2 N = 2026-11-30, 26 days out.) The renewal-notice obligation's due date, when present, MUST equal N for that contract — seeded and asserted (O-1, O-6).
- **Extraction suggestion table**: a fixed map keyed by document id; C-3-v1 → exactly the 7 rows above with fixed confidences and fixed anchors (page + excerpt). No stochastic generation; re-running extraction on the same document version returns the same table (idempotency-key replay returns the original job).
- **Assist degradation ladder**: config `assistEnabled: false` → runExtraction succeeds with `degraded: true, degradedReason: 'unavailable'`, zero suggestions (rung 4 — the UI renders the manual-path notice) · `consentGranted: false` → PERMISSION naming the extraction capability class (credential-contract §2 kind-not-vendor language) · `quotaExhausted` → RATE_LIMIT · `quotaWarn` (≥80% of window consumed) → run returns only confidences ≥ 0.77 (5 of 7 rows — rung 2, labeled in-UI). The manual path (createObligation/updateContract) is never metered and works in every configuration.
- **Bilingual search normalization** (rtl-rules §4, applied to list search): strip tashkeel; أ/إ/آ → ا; ة → ه; ى → ي; matching runs on normalized forms of both scripts' fields. Fixture assertions: query "ريم" returns Reem Properties (Arabic name match); query "Reem" returns the same row (Latin match); query "الوفاء" and "Al-Wafa" both return C-3's counterparty. No result ever fabricates the other language's field.

## Behavior

- `createContract`/`uploadDocument`/job submits replay idempotency keys — double-submit returns the original result, never duplicate records.
- `updateContract`/`updateObligation`/`updateCounterparty` stale baseVersion → CONFLICT carrying both payloads in details.
- `runExtraction`: paced 120ms/page progress (22 pages → determinate progress over ~2.6s, cancellable); partial failure via `failAfterSuggestion: n` config → succeeded-with-partial (n suggestions delivered, rest marked per-item retryable — async-contract §4).
- `resolveSuggestion` with `action: 'accept'` creates the obligation/metadata with provenance 'assist' + assistSuggestionId; with `edit` → activity detail "assist-proposed, human-edited"; `dismiss` retains the row in state dismissed (never purged).
- `recordExecution`: requires an approved ReviewStep on the contract (else VALIDATION naming the gate); on success the contract activates and the dormant obligation schedules compute immediately (the Seal Settles moment's data event).
- `markTerminated`: closes open obligations (seed C-6: O-13, O-14) and returns the closed list; closed obligations never compute reminders.
- `recordRenewalTerm`: appends a TermRecord; with `correctionOf` → activity 'correction-recorded' referencing the erroneous term (C-6 fixture).
- `exportRegister`: 7-day artifact expiry; expired artifact (A-1) → NOT_FOUND + regenerable path; `failExportScopeOnce` config → partial bundle with per-scope retry.
- `getUsage`: window "monthly"; extractionRuns 14 of 20 (70% — below warn; `quotaWarn` config lifts to 17/20 for the 85% warning fixture); manualObligationsCreated unmetered (renders NO meter — 06 rule).
