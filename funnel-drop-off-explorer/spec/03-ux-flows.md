# 03 — UX Flows: funnel-drop-off-explorer

SME-C pass · Critical paths with edge cases, failure modes, and recovery. Every path is the justification source for adapter operations in 07a/07b; the bidirectional traceability tables at the end prove zero orphans in BOTH directions (flagship obligation). All flows run on the desktop-first exploration canvas (≥1280px, keyboard-first) unless the tablet review view (≥820px) is named; the review view carries read-and-annotate posture only — no funnel authoring, no taxonomy mutation below desktop (04).

## CP-1 — First insight in one sitting: sample or source, compose, render, select (analyst; canvas)

1. **Entry**: `getSession` routes by role — analyst → FUNNELS HOME (S2), admin → FUNNELS HOME with the sources badge visible, all roles → first-run lands on the P22 onboarding checklist with four persona entry paths (02). The canvas never opens empty: the home lists saved funnels with their latest computed headline (overall conversion + trend arrow + freshness chip).
2. **Data posture check (LOOP-5 primary = paste sample)**: if no event source is bound and no sample imported, the canvas header carries the data-state chip ("No event data yet — paste a sample or bind a source") and the FUNNELS HOME hero offers the paste path. `importEventSample` (CSV/TSV with column mapping preview: event name, user key, timestamp, property columns) is a **Job** (async-contract §2): determinate per-row progress ("importing row 40 of 120"), `awaiting-input` on ambiguous rows (unmapped property column → per-column choice: map to a taxonomy axis or skip — never a silent drop), partial-results policy per async-contract §4. A bound source (08 N1) is the abstract upgrade; paste stays primary at v1.
3. **Compose the funnel**: NEW FUNNEL opens the canvas with the Step Composer (06) — taxonomy search (`listTaxonomyEvents`, Arabic-normalized — rtl-rules §4) picks events in order; each step chip carries the event's bilingual labels, status, and usage count; step settings per composer: ordering mode (sequential / strict / any — the vendor-documented semantics, 01 §3 q2), conversion window (seeded 7 days, bounded 1h–366d per the documented vendor range, 01 §3 q16), optional per-step property filters, and global filters. `saveFunnel` VALIDATION: steps non-empty, all events exist and are `active` (or explicitly acknowledged-deprecated with the impact note — the CP-4 gate), window within bounds.
4. **Render**: `computeFunnelMetrics` returns per-step counts, step conversion rates, drop-off counts and rates, largest-drop-off step (absolute decrease — the documented craft, q20), slowest step (median transition time — q20), and overall conversion; the Cascade renders strata in order with the lost-flow ribbons between them (06/13). The render states its basis in the header: source (bound name or "pasted sample"), date range, window, freshness (11 §D7).
5. **Select the seam**: j/k (or ↑/↓) move focus across seams (the gaps between strata); Enter opens the seam dossier in place — breakdown axis picker, displaced-paths ribbon, time-to-convert distribution, and the anneal launcher (CP-2). The largest seam is pre-badged ("largest drop-off — 86 of 271") in text+icon, never color alone.

**Edge cases**: paste with mixed-script event names (English canonical + an Arabic alias column) → mapping preview shows the normalized match per row with confidence, ambiguous rows park `awaiting-input` (both candidates shown); pasted sample with events not in the taxonomy → the import proposes creating `proposed`-status events (governance path, CP-4) rather than dropping rows; funnel composer references an event deprecated WHILE composing (live taxonomy event) → the composer row flags it inline with the impact note and blocks save until acknowledged; conversion window beyond the pasted sample's span → a coverage notice renders ("sample covers 21 of the 28 requested days") — honesty over silence; duplicate funnel name → suffix proposal, never silent overwrite.
**Failure modes**: importEventSample VALIDATION (malformed row/timestamp) → row-linked errors quoting the offending row; RATE_LIMIT (import frequency cap) → count + reset window; NETWORK mid-import → job reconcile (idempotency key; async-contract §5); computeFunnelMetrics NOT_FOUND (funnel deleted by a teammate) → safe-state + list re-sync; VALIDATION (zero-step funnel, window out of bounds) → rule-named inline errors.
**Recovery**: imports are resumable jobs (retryJob scoped to failed rows); funnel drafts autosave (P10) with the restore prompt on return; nothing is committed until save.

## CP-2 — The exploration loop: seam dossier — breakdowns, displaced paths, time (analyst; canvas keyboard-first)

1. **Seam dossier opens** (Enter on a seam; S3 in-canvas panel — never a route: the cascade is the decision context, 04 IA decision). Header facts: step pair, lost count, baseline drop-off rate, support size ("First Search → Add to Cart — 86 lost of 271, 31.7% of the step").
2. **Breakdown** (B): `breakdownFunnelStep` with the chosen axis (taxonomy-declared segmentable properties render as the axis picker; non-segmentable properties gray with reason "not declared segmentable — ask your taxonomy owner"). Rows: segment size, drop-off rate, delta vs baseline, sorted by separation (|delta| × sqrt(coverage)) descending, capped (seeded 12 rows; the cap is a UI rule, the engine returns all). Each row is a candidate segment: Enter drills it to a preview (CP-3 compare), S saves it as a segment.
3. **Displaced paths** (the ribbon, q19 precedent): `getStepTransitionDetail` returns the ranked next-events of the lost users ("where they went instead"): "App Exited 31 · Restaurant Page Viewed 19 · Support Chat Opened 11…" — each ranked row carries count and share; Enter on a path event opens its taxonomy card (CP-4 context) — the ribbon teaches what the leak's users did INSTEAD, at the aggregate level (LOOP-10: no session replay, stated plainly in the panel footer).
4. **Time-to-convert** (same dossier section): median and p90 transition time per the fixed bucket edges (07c §2.4), with the "slowest step" cross-reference ("median 41m — the slowest transition in this funnel").
5. **Live re-query discipline**: changing the date range or window re-runs `computeFunnelMetrics` and patches the cascade IN PLACE (strata settle, seams re-badge); the dossier closes if its seam's step pair changed identity, with a polite notice ("the funnel changed underneath — reselect the seam").
6. **Trend context**: T opens the trend strip (getFunnelTrend — windowed conversion over the range; the seasonality question vendors document, q2); the strip is sparkline + per-window rates as text, never a replacement for the cascade.

**Edge cases**: seam with zero lost users (100% conversion) → the dossier renders the "no leak at this seam" state with time-to-convert only (P01 discipline — an empty that names what exists); breakdown axis with a single value → renders the degenerate row with "no separation possible — one value in this axis"; displaced paths where lost users had NO subsequent event → the "left the product" row ranks with its count (an honest first rank, not an error); breakdown on the pasted sample with coverage gaps → the coverage chip rides the panel (11 §G); two analysts breaking down the same seam concurrently → read-only operations, no conflict possible (the canvas is a query surface; conflicts exist only on writes — CP-3/CP-4).
**Failure modes**: breakdownFunnelStep VALIDATION (axis not segmentable / step index out of range) → rule-named; getStepTransitionDetail NOT_FOUND (funnel archived) → safe-state + link to the archived definition; RATE_LIMIT (query spam guard) → count + reset; NETWORK → in-canvas retry with the previous render retained (queries never blank the canvas — the last good render stays with a staleness chip).
**Recovery**: all CP-2 operations are reads — recovery is re-query; the canvas retains the last good state per region and names staleness honestly (P02-adjacent discipline).

## CP-3 — The anneal: run, read the trace, chain to segments and cohorts (analyst; canvas + segment workshop)

1. **Launch** (A on a seam): the anneal launcher renders the engine's parameters as EDITABLE POLICY (07a AnnealPolicy per-workspace, versioned): support floor formula (seeded `max(30, 2% of the seam population)`), improvement epsilon (seeded 0.02), depth cap (seeded 4), excluded axes (seeded: none). `annealSegment` runs synchronously (≤2s budget, 10) with the run's progress rendered as iteration landings on the Anneal Spine (06/13).
2. **The Spine renders the trace**: each iteration shows every evaluated candidate with its size, drop-off rate, excess, and separation score; the ADMITTED predicate pinches the population band (the signature motion, 05); rejected candidates render below with their reason ("no improvement over the current chain", "below the support floor — 20 of 271", "protective segment — negative excess"). The final chain carries: predicates in admission order, chain size, chain drop-off rate, excess vs baseline, and **excess headcount** ("~17 drop-offs above baseline expectation in this segment").
3. **Honesty rails on the Spine**: the correlation-honesty sentence renders under every chain (11 §D1 — association, not causation, in both locales); the support floor and epsilon are visible on the Spine header; the run names the engine version and the data basis (source + range + freshness).
4. **Chain → segment**: S saves the chain as a SegmentDefinition (predicates + origin metadata: the funnel, seam, and run that produced it — provenance by construction); the segment lands in the workshop library (S4).
5. **Chain → cohort + user drill**: from the segment, "Create cohort" calls `saveCohort` (the segment's user set at run time, materialized as pseudonymous keys); `listCohortUsers` paginates the drill (user key, declared property values, entry/exit timestamps) — PII posture: pseudonymous keys ONLY, no emails/phones/names (07a; 09 privacy posture).
6. **Compare** (C): `compareSegments` with segment A (the chain) vs segment B (another saved segment, a breakdown row's population, or the complement) at the same seam — the CompareBoard renders aligned drop-off rates, sizes, excesses, and the delta sentence ("web-new users drop 28.3 points above baseline; their complement drops 8.0 points below it").
7. **Anneal history**: every run is listed in the workshop (its parameters, its chain, its data basis) — reruns on drifted data are NEW runs, never edits (evidence discipline, 07a).

**Edge cases**: anneal on a seam below the support floor entirely (seam population < 30) → the launcher refuses honestly ("seam population 24 — below the minimum support floor of 30; widen the date range or the window"); anneal that admits nothing (all candidates below epsilon) → the "no separating segment found" result renders WITH the full candidate table (the null result is evidence, not failure — 11 §A); chain that empties a cohort on drift (users aged out of `new`) → cohort rows carry a freshness basis, the cohort list names materialization date; comparing segments from different funnels → allowed only at the same step-pair semantics (the comparison VALIDATION names the mismatch); concurrent saves of same-named segments → suffix proposal; the anneal run exceeding 2s on huge seams → job-shaped continuation with progress (async-contract §1 threshold), never a fake spinner.
**Failure modes**: annealSegment VALIDATION (policy malformed: epsilon ≤ 0, depth cap > 8, excluded axes unknown) → rule-named; PERMISSION (analyst role cannot change workspace anneal policy — admin) → lock state with request-access; saveCohort RATE_LIMIT (cohort minting guard) → count + reset; listCohortUsers NOT_FOUND (cohort expired by retention policy) → named expiry with the segment path to re-materialize; NETWORK → anneal re-runs are idempotent by input hash (07c §3) — a re-submitted identical run returns the original result.
**Recovery**: runs are immutable evidence rows; failed runs retry as new attempts that reference the same input hash (dedup by the mock, 07c §3).

## CP-4 — Taxonomy governance: lint, fix, deprecate, impact-check (data engineer + admin; taxonomy manager)

1. **Lint report** (S6 surface; L from anywhere): `getTaxonomyLintReport` renders violations grouped by class: naming convention (not `[Noun] [Past-Tense Verb]`, wrong casing, noun-only, ambiguous actor), bilingual completeness (missing/empty labelEn or labelAr), property health (undeclared property values observed in data, type mismatches), and governance (active funnels referencing deprecated events; ownerless events). Each violation carries the event card, the rule text, and the fix action.
2. **Fix inline** (P06): `upsertTaxonomyEvent` edits canonical name / labels / description / owner / properties with a synchronous lint result on the draft (violations block publish as ERROR class; warnings render but do not block); the diff preview shows the event's usage counts across saved funnels before commit ("used by 3 funnels, 41,203 events in range").
3. **Rename safety**: renaming an event updates canonical name; saved funnels referencing the OLD name return an impact list at the edit gate (which funnels, which steps); the rename requires choosing the migration (update references — default — or fork a new event and deprecate the old).
4. **Deprecate**: `setTaxonomyEventStatus(deprecated)` on an event referenced by active funnels → VALIDATION with the reference list and explicit resolution options (acknowledge-and-keep references as `legacy`, or migrate them now); deprecated events render with the legacy glyph in every composer/search result and are excluded from NEW funnel steps (07b rule 7).
5. **Proposed events from imports**: events observed in paste-imports but absent from the dictionary land as `proposed` cards in the taxonomy manager; activating one requires the full bilingual label set (lint-gated).
6. **Live taxonomy → live canvas**: every taxonomy change appends to the activity trail (P17) and emits a workspace event (subscribeWorkspaceEvents) so open canvases flag staleness of rendered metrics ("taxonomy changed after this render — re-run").

**Edge cases**: rename to a name that collides with an existing event (the `Song Played`/`song played` class of incident, q10) → VALIDATION naming the collision; deprecating an event used by an ARCHIVED funnel → allowed without gate (archived funnels don't run); an event with zero usage (observed 0 times in range) → the lint's "dead event" warning with the deprecate shortcut; property value observed in data but not declared (categorical axis) → the "undeclared value" lint row with one-tap declare; two engineers editing the same event concurrently → CONFLICT with both drafts shown (P10-style compare), first-write wins, second re-decides.
**Failure modes**: upsertTaxonomyEvent VALIDATION (blocking lint errors, label gaps, invalid property type) → rule-named with the failing rule text; setTaxonomyEventStatus PERMISSION (only admin/engineer-owner may deprecate — 07b role model) → lock state; CONFLICT (concurrent edit) → both-shown compare; NETWORK → the edit queues (P20) and reconciles against the versioned dictionary.
**Recovery**: the taxonomy is versioned data — every change is a new version with an activity entry; restores are reverts (new versions), never edits (07a).

## CP-5 — Narrate, save, share, export: the evidence loop (analyst + PM + lead; canvas → analyses feed → export)

1. **Narrate** (N on a chain or a saved analysis): `narrateDropOff` composes the drop-off narrative — the conditionally-AI surface. Unbound (the shipped default): `engine: 'template-metrics'`, the deterministic bilingual template composed from the run's numbers (11 §D1-D2 verbatim). Bound: `engine: 'model-assisted'` narrative over the SAME evidence, provenance displayed, never replacing the numbers. Stop/Regenerate available from the first token when streaming (ai-native-patterns §2); the narration region is reserved (CLS ≤0.02, 10).
2. **Save the analysis** (`saveAnalysis`): the evidence pack = funnel + parameters (range, window, ordering) + the anneal run (full trace) + optional narrative + author note. Saved analyses are reproducible: re-opening recomputes against current data and names drift ("same parameters; data moved 6 days — numbers refreshed, chain unchanged" or "chain no longer reproduces — the leak moved", 11 §D6).
3. **Share**: analyses land in the feed (S8) with author, date, and headline; digest notifications (`listNotifications` P21 ladder) tell the team a new shared analysis landed (digest tier — never instant ping spam); Sara opens the link in the review posture (≥820px), reads the narration, expands the Spine, and comments inline on the analysis note (annotations are part of the analysis entity — lightweight, no thread machinery at v1, 12 Q-11).
4. **Export** (`exportAnalysis`): a Job producing the bilingual evidence artifact — funnel parameters, cascade figures, the full anneal trace, the narrative, the correlation-honesty sentence, provenance and engine versions — with a declared expiry window (async-contract §2), delivered in-context or via the abstract artifact destination (08 N3).
5. **The honesty stack on every artifact**: source basis, freshness, engine versions, provenance, and the association-not-causation sentence — the export is leadership-grade by construction (Layla's QBR artifact, 02).

**Edge cases**: narration with the model bound but rate-limited mid-stream → partial retained, marked partial, template-metrics offered as the completion (ai-native-patterns §2 stall/failure rules); saving an analysis whose funnel was archived meanwhile → the save carries the archived definition inline (the analysis is self-contained evidence); export of an analysis with coverage gaps → the artifact carries the coverage note verbatim; sharing to a user outside the workspace → NOT permissioned at v1 (share-by-link within workspace only — honest boundary, 12 Q-12).
**Failure modes**: narrateDropOff RATE_LIMIT (narration allowance) → P14-style transparency (count, reset, upgrade note) with the template path always available (the ladder's rung 2 is the DEFAULT here — the deterministic narration never walls); exportAnalysis PERMISSION (viewer-role cannot export) → lock state; NETWORK → jobs reconcile; saveAnalysis VALIDATION (empty pack — no chain, no funnel) → rule-named.
**Recovery**: exports are jobs with retry scoped to the artifact build; partial narrations are never silently promoted to complete (ai-native-patterns §2).

## CP-6 — Admin spine: sources, people, notifications, jobs + the resilience walkthrough (admin; documented and tested)

1. **Sources & samples** (S7): `listEventSources` renders each bound source's health per credential-contract lifecycle (unverified → active → expiring-soon → expired/failed — capability language only, kind-not-vendor); the paste-sample path lives here as the v1 PRIMARY; source freshness chips ride every surface that renders its data (11 §G).
2. **Anneal policy** (workspace-scoped, versioned): the admin edits support floor / epsilon / depth cap / default excluded axes (CP-3's launcher reads this as the default policy); changes require the before/after preview over the seam in view (the policy renders as the same sheet analysts see — inspectability) and append activity entries.
3. **People**: `listUsers` / `inviteUser` / `updateUser` — two structural roles (analyst / admin) + viewer (read-and-annotate for PM/lead consumption, 04); role changes are ledger entries.
4. **Notifications** (P21 ladder, S10): digest tier = new shared analyses, taxonomy lint digests (weekly), source health changes; instant tier = none at v1 (an exploration tool has no page-worthy emergencies — recorded deliberately, 12 Q-13). `listNotifications` + `markNotificationsSeen`; tier control per class per user.
5. **Jobs center** (S9): `getJob` / `retryJob` / `cancelJob` — sample imports and exports; retry scoped to failed rows/items (async-contract §4).
6. **Activity** (P17): `listActivity` — every consequential mutation (funnel save/archive, segment/cohort save, taxonomy version, policy publish, analysis save/share, exports) appends actor-action-target-timestamp; filterable; the accountability surface for the taxonomy's change history (Reem's "who broke the funnel" answer).
7. **Live events**: `subscribeWorkspaceEvents` drives canvas staleness flags (taxonomy/source/policy changes), job state patches, and feed updates; the mock replays a fixed event script deterministically (07c §4).
8. **Offline discipline (P20)**: the canvas is query-first (reads never queue — the last good render persists with staleness chips); writes that queue offline are bounded: analysis saves and annotations; taxonomy edits queue with per-item state and reconcile against the versioned dictionary (CONFLICT surfaced honestly on drift).
9. **Full walkthrough (00 §success-signal 2, release-test fixture)**: paste-import 120-row sample (116 imported, 2 failed rows quoted, 2 awaiting-input resolved — 07c §1) → compose the 5-step funnel (sequential, 7-day window) → cascade renders 400 → 348 → 271 → 185 → 121 (30.25% overall) → largest seam selected (First Search → Add to Cart, 86 lost, 31.7%) → breakdown by platform/locale/tenure (locale NULL — the honest null axis fixture) → displaced paths read (App Exited 31 tops the ribbon) → anneal run (policy defaults) → chain `[tenure = new ∧ platform = web]` (60 users, 60.0%, +28.3pts, ~17 excess; iteration 1 admits tenure=new [sep 0.0764 over platform=web 0.0661], iteration 2 admits platform=web [chain sep 0.1330 vs 0.0764], iteration 3 rejects locale=ar [no improvement: 0.1071 < 0.1330]) → narration (template-metrics, provenance chip) → segment saved → cohort minted → user drill (60 pseudonymous keys) → analysis saved → exported (artifact, 7-day expiry). Then the degradation re-run: source unbound + narration unbound + artifact destination unbound — paste sample in, full anneal, template narration, artifact download — the same evidence journey completes. Total: 8 surfaces, zero stalls, replayed twice byte-identical (07c §5).

Reverse check performed at Critic pass — zero orphans in either direction (35/35 operations; 35/35 traced step-groups).

**Design notes recorded at the Critic pass (contract shape, not drafting noise):**

(a) **Segment persistence rides the analysis write.** `SegmentDefinition` entities are created through `saveAnalysis` — every evidence pack carries its `segments[]` block with origin metadata (funnel, seam, anneal run) — and are listed in the workshop via `listAnalyses` filtered to segment-bearing packs. There is no separate `saveSegment` method: a segment without provenance is exactly the unsaved cohort-chip the incumbents produce (01 §2 gap column), and forcing it through the analysis write is what makes provenance structural. Materialization to a user set is the separate act (`saveCohort`) because it snapshots a population at a moment — a different entity with a different lifecycle (07a).

(b) **The workspace anneal-policy default publishes through `annealSegment` with `persistAsDefault: true`.** The policy is a per-run input first (every run names the policy it ran under — inspectability); the admin surface publishes the workspace default by running the policy against the seam in view (the run's own before/after trace IS the required preview), with `persistAsDefault: true` making it the new default for future launchers. Every publish appends an ActivityEntry; `getSession` returns the current default so launchers open with it. This keeps the op count at 35 with zero policy side-doors (07b rule 13) — the alternative (a dedicated settings-write method) was rejected at op-count review as a 36th operation that adds no flow (the launcher edit IS the settings surface).

## Failure-mode → error-class mapping (feeds 07b/11)

| UX failure | Error class | User-facing surface |
|---|---|---|
| Malformed paste row; zero-step funnel; window out of bounds; non-segmentable breakdown axis; anneal policy malformed (epsilon ≤ 0, depth cap > 8); taxonomy lint ERROR class; label gaps on activate; rename collision | ValidationError | field/row/rule-linked inline error naming the failed rule |
| Funnel/archived analysis/cohort/expired artifact/event id absent or resolved | NotFoundError | safe-state + list re-sync + next action |
| Analyst on admin surfaces (policy default publish, people); viewer on any write; suspended user | PermissionError | lock state with request-access action |
| Concurrent taxonomy edit; concurrent same-named saves racing the suffix; cohort re-materialization racing retention sweep | ConflictError | both-states compare, explicit re-decide |
| Import frequency cap; query spam guard; cohort minting guard; narration allowance; export frequency | RateLimitError | count + window + reset copy (P14-style transparency) |
| Offline / transport drop mid-write / source freshness failure surfaced to UI | NetworkError | P20 queue with per-item state + honest reconciliation; canvas retains last good render with staleness chip |
| Anything else | UnknownError | correlation-id copy (copy-voice §1.4) |
